# 02 · 数学模型白皮书

> 目的：把 `dsh-recency-guard` 里每一个量化模型的**假设、定义式、参数、失效条件、复杂度、验证方法**
> 写成一张可查的账。读它的目的不是为了复用公式，而是为了知道**每个公式在什么情况下会撒谎**。
>
> 全部公式与参数均来自本仓库源码，非教科书转抄。

## 0. 先立三条元规则

在谈具体模型之前，三个贯穿全文的元规则（它们决定了模型「能不能用」）：

### 规则 1：模型必须自带失效条件

本项目不接受「永远输出一个数」的模型。每个模型都要回答：
**在什么输入下它不可判定？** 不可判定时返回 `defined:false` + `reason`，`value === null`。
「无数据当 0」是本项目明令禁止的反模式（`observability.ts:72 Metric<T>`）。

### 规则 2：样本不足时必须降级，而不是加戏

两个降级手段，缺一不可：

- **`confidence = 1 − 1/√n`**（`observability.ts:108 sampleConfidence`）：样本充分度指数，
  不是置信区间的覆盖概率，只用来驱动前端「低置信」标记。
- **`displayDigits ≈ log10(n) + 0.5`，夹在 [1,4]**（`observability.ts:119 displayDigits`）：
  3 个样本只报 1 位有效数字。内部值保留 4 位小数只为**可逐字节比对**，显示位数不得超出
  样本能支撑的分辨率。

### 规则 3：复杂度必须可辩护

每个模型在头注里写复杂度，否则下一个维护者会「优化」错方向。
本项目用 `.cycles/config.yml` 的 `complexity_budget: 100` 作为硬预算。

## 1. 诚实边界契约：`Metric<T>`

| 项 | 内容 |
|---|---|
| 定义 | `value: T \| null` 且 `defined: boolean`，两者必须一致 |
| 假设 | 「不可判定」与「值为零」是两个不同的事实 |
| 失效条件 | 构造器之外手写字面量会破坏一致性 |
| 复杂度 | O(1) |
| 验证 | `undefinedMetric` / `definedMetric` 两个构造器独占赋值路径 |

这不是统计模型，而是**所有模型的输出契约**。它让「无法评估」永远不等于「通过」。

## 2. 崩溃率 `crashRate`

| 项 | 内容 |
|---|---|
| 定义 | `crashes / starts` |
| 假设 | 每次启动是独立观测 |
| 失效条件 | 观测数 0 ⇒ 不可判定 |
| 复杂度 | O(n) |
| 验证 | `tests/unit/observability-math.test.ts` |
| 局限 | 整体比率把「很久以前崩过一次」与「刚刚连崩两次」算成同一个数——**因此它不是唯一指标** |

---

## 3. 崩溃压力 `crashPressure`（EWMA）

| 项 | 内容 |
|---|---|
| 定义 | `EWMA(0/1 启动信号)`，`α = 1 − 2^(−1/H)`，`H = 5` 次启动 |
| 假设 | 时间局部性：越近的启动越重要 |
| 失效条件 | 无观测 ⇒ 不可判定 |
| 复杂度 | O(n) |
| 参数 | 半衰期 H=5（每次启动信号，5 次启动后权重减半） |

**为什么不是 `crashRate`**：crashPressure 把启动序列编码成 0/1 信号再做指数遗忘，
表达「多久算近期」。全平稳序列的 0 是**真值**（有数据且每次都没崩），与不可判定的
null 语义不同（cycle-4）。这是「区分 0 与 null」在时间序列上的具体应用。

## 4. 崩溃间隔统计 `crashIntervalStats`

| 项 | 内容 |
|---|---|
| 定义 | 间隔序列的中位数 / 均值 / CV / MAD / IQR |
| 假设 | 间隔可加、同一时基 |
| 失效条件 | 崩溃数 < 2 ⇒ 不可判定；全 0 间隔 ⇒ CV 不可判定 |
| 复杂度 | O(n log n)（精确分位数） |

**分位数为什么用精确排序 + 线性插值而不是 P² 算法**：P² 是为「流式、n 很大、内存受限」
设计的近似算法，本模块 n 通常 ≤ 50，精确值更可审计（契约测试要逐字节比对）。

## 5. CUSUM 变点 `cusumChangePoint`

| 项 | 内容 |
|---|---|
| 定义 | `S_i = max(0, S_{i−1} + (k·q − g_i))`，`q = P75(g)` |
| 假设 | 间隔独立同分布、变点后均值下移 |
| 失效条件 | 崩溃数 < 2、`q = 0`（同刻崩溃）⇒ 不可判定 |
| 复杂度 | O(n log n) |
| 基准 | **P75 而非中位数**（cycle-3 实测） |

**为什么 P75**：中位数让一半样本低于基准，容差后几乎无法累计证据——检测器对真实变化
**结构性失明**。P75 之下只有 25% 样本，只有持续显著变密才推得过阈值。
这是本项目最有代表性的一次「阈值选择决定模型成败」的实证。

## 6. 崩溃间隔生存分析 `intervalSurvival`（指数 + Weibull）

这是本项目数学含量最高的模型，单独成文件 `src/survival.ts`。

### 6.1 模型

把相邻崩溃间隔 `g_i` 当作**独立同分布的非负寿命**（无删失：每次间隔都完整观测到）。
两个拟合：

**(a) 指数模型（齐次泊松过程）**
```
λ̂ = 1/ḡ          （MLE，闭式）
h(t) = λ 恒定       ⇒ 无记忆：下一次崩溃不取决于距上次多久
理论 CV 恒为 1     ⇒ cvObserved 偏离 1 就是「指数假设被数据拒绝」的直接证据
```

**(b) Weibull 模型**
```
h(t) = (k/λ)(t/λ)^(k−1)
```
形状 `k` 用**轮廓似然 MLE**：对固定 k，`λ̂(k) = ((1/n)Σ g_i^k)^(1/k)`；
代入得 k 的得分方程
```
g(k) = Σ w_i·ln g_i / Σ w_i − 1/k − mean(ln g) = 0,   w_i = g_i^k
```
`g(k)` 在 k 上严格单调递减，用**对数空间二分**求解（k 跨 6 个数量级，线性二分前 20 步几乎不动）。

### 6.2 语义（为什么值得算）

| 形状 k | 危险率 | 含义 | 结论 |
|---|---|---|---|
| k < 0.9 | 递减 | 过离散 ⇒ 崩溃**成簇**（连锁）或存在未观测异质性 | 别只等下一次，要去查簇 |
| 0.9 ~ 1.1 | 恒定 | 无记忆（泊松） | 崩溃在时间上互不相关 |
| k > 1.1 | 递增 | 欠离散，比泊松更规则 | 多见于固定周期定时任务/固定时长负载 |

### 6.3 失效条件（全部返回 `defined:false`，绝不硬凑）

- 间隔数 < 3：两参数似然在 n=2 时没有残差自由度，形状只是两点之比的函数。
- 存在 0 间隔（同刻多次崩溃）：`ln 0 = −∞`，对数似然发散。
- 全部间隔相等（方差 0）：`g(k) ≡ −1/k < 0` 无根，`k → ∞`，形状不可辨识。

### 6.4 数值稳定性（工程细节，都是踩过的坑）

| 技术 | 为什么 |
|---|---|
| log-space 二分（`mid = sqrt(lo·hi)`） | k 搜索区间 [1e−3, 1e3]，线性二分前 20 步几乎不动 |
| `softmaxMean`（max 平移） | 权重 `w_i = exp(k·ln g_i)` 直接算会溢出 |
| `logSumExp` | 同理 |
| Lanczos 近似 `lgamma` | 只需要 `Γ(1 + 1/k)`，域 x ≥ 1，自实现零依赖 |
| `shapeAtBound` 显式标注 | k 撞搜索上界 1000 是**边界伪值**不是估计值，绝不能报成「k=1000」 |

### 6.5 复杂度与验证

- 复杂度：O(iters · n)，iters 固定 100。
- 验证：`tests/unit/observability-math.test.ts` 的 survival 断言，与实现同址。
- 局限：假设 i.i.d. 无删失。真实崩溃若有「累积损伤」（插件越崩越易崩），
  i.i.d. 假设被违反——这恰恰是 `k < 1`（成簇）可能暴露的信号。

## 7. 间隔趋势 `intervalTrend`

| 项 | 内容 |
|---|---|
| 定义 | `ratio = EWMA_H(g) / median(g)`（去暖机偏置） |
| 假设 | 近期水平可用指数遗忘估计 |
| 失效条件 | 间隔数 < 2、中位间隔 0 ⇒ 不可判定 |
| 复杂度 | O(n) |

与 `cusumChangePoint`、`crashTrend` 的分工：CUSUM 找「持续漂移从哪开始」，
回归斜率找「整体方向」，控制带找「**哪一次**越界」。三者互为视角，不互相替代。

## 9. 休哈特控制带 `controlBand`（单值-MR 图）

| 项 | 内容 |
|---|---|
| 定义 | 中心线 `x̄`；`UCL/LCL = x̄ ± 3σ̂`；`σ̂ = MR̄ / 1.128`（`d₂(2)=1.128`，n=2 无偏常数）；`MR = |相邻间隔差|` |
| 假设 | 相邻间隔的变异主要来自偶然原因 |
| 失效条件 | 间隔 < 2 ⇒ 无 MR 可算 ⇒ 不可判定；`σ̂ ≤ 0`（全等）⇒ 带宽为 0 是**真值**（完美周期过程），不是不可判定 |
| 复杂度 | O(n) |
| 验证 | `tests/unit/observability-math.test.ts` |

**质量控制定位**：区分**偶然原因（common cause）**与**特殊原因（special cause）**。
`breaches` 字段点名「第几个间隔低于 LCL」，正是「崩溃变密」被点名的位置。

## 10. 马尔可夫链 `markovAnalysis`

`src/markov.ts` 把生命周期迁移历史建模成马尔可夫链。

### 10.1 为什么是马尔可夫而不是直接数迁移次数

直接数次数只能回答「哪个迁移最多」，回答不了「这个系统的**行为模式**」：

- **转移概率矩阵**给每个阶段一个「去向分布」——monitoring 是健康值守（80% 留在自己）
  还是高危巡逻（40% 掉进 crashed），一行读数见分晓；
- **平稳分布**（幂法迭代）回答「长期来看守护花在哪」：若 crashed 的平稳占比高，
  说明这个 profile 的插件生态在持续引发崩溃，**归档/重装才是根治**，
  面板反复「恢复成功」只是止痛。

### 10.2 定义

阶段集合 `S = {idle, monitoring, crashed, deciding, stabilizing, recovered}`（6 个）。
计数矩阵 `C[from][to]`，概率 `P = C / rowTotal`。
平稳分布满足 `π = π·P`，用**幂法**迭代 `π_{k+1} = π_k·P` 求解。

### 10.3 参数与收敛

| 参数 | 值 | 理由 |
|---|---|---|
| `POWER_ITERATIONS` | 200 | S=6 的随机矩阵几十次内必收敛，200 是安全上限 |
| `EPSILON` | 1e-9（L∞ 距离） | 对四位小数显示足够 |
| 初始分布 | 均匀 | 幂法对初始分布不敏感（不可约 + 非周期时） |

### 10.4 诚实边界（**注意：源码注释与实现有漂移**）

`markov.ts` 头注写着「样本不足（迁移数 < 阶段数下限）或无法收敛 ⇒ `defined:false`（null）」，
但实现（`markov.ts:118-135`）实际是：

- `stationary` **只在 `samples > 0` 时计算**；空历史 ⇒ `stationary === null`（有测试钉住，
  `tests/unit/observability-math.test.ts:467`）；
- **没有「迁移数 < 阶段数下限」的门槛**——1 条迁移也会算出平稳分布；
- **未收敛时仍然返回 `stationary`**，只是 `converged: false`。即「收敛与否」由
  `converged` 字段表达，而不是由 `null` 表达。

> **这是一处文档-实现漂移（漂移类型：头注承诺的强保证 > 实现实际给的弱保证）。**
> 研究文档的立场：**以实现为准**，并把它记为待修项（见 `07` 的 RQ4 风险登记册）。
> 读者不应照着头注的「阶段数下限」去依赖它。

其余**确实成立**的诚实边界：

- 行和为 0 的孤立阶段（从未迁出）不参与平稳分布归一——用它自己的**自环概率 1**
  处理（吸收态语义），但在 label 里如实说明「无迁出样本」。
- 白名单外的阶段名（旧版本/手改数据可能带进来）**丢弃并计数**，计入 samples 会虚增置信度
  （`tests/unit/observability-math.test.ts:470` 的 `mkJunk` 用例）。

### 10.5 复杂度

- 构建 O(T)（T = 迁移数）；幂法 O(K·S²)，K ≤ 200，S = 6。S 是常数 ⇒ 整体线性于迁移历史长度。

### 10.6 局限

马尔可夫性假设「下一阶段只依赖当前阶段」。真实守护过程中，历史（累积崩溃计数）
显然影响决策——所以这是**描述性**模型，不是预测模型。它的用途是「行为模式体检」，
不是「下一轮会崩吗」。

## 11. 崩溃趋势 `crashTrend`

| 项 | 内容 |
|---|---|
| 定义 | 对**相邻崩溃间隔**做简单线性回归斜率，归一化到 [−1,1] |
| 假设 | 间隔线性变化 |
| 失效条件 | 间隔数 < 2 ⇒ slope 记 0（用 `trendMetric` 包装为不可判定） |
| 复杂度 | O(n) |
| 阈值 | `TREND_THRESHOLD = 1` 小时/次 |

**为什么回归间隔而不是崩溃时刻**（`lifecycle.ts:418`）：计数无法区分「3 次崩溃集中在 1 分钟」
与「3 次崩溃分散在 3 个月」。间隔序列携带「变密/变稀」的方向信息——
`rawSlope < −threshold ⇒ worsening`，`> threshold ⇒ improving`。

> 本项目在 CLAUDE.md 中明确记了一条坑：**回归时间戳或累计计数都是错的，必须回归相邻崩溃间隔**——
> 只有间隔携带「变密/变稀」方向（斜率恒 1 / 方向丢失是实测踩过的坑）。

## 12. 稳定性评分 `stabilityScore`

| 项 | 内容 |
|---|---|
| 定义 | `score = stageWeight × exp(−λ · recentTransitions)`，`λ = ln(2)/3` |
| 假设 | 状态是「健康度」的**序数代理**；刚发生迁移说明状态还在震荡 |
| 失效条件 | 无（总是有值），但**不是崩溃率** |
| 复杂度 | O(1) |
| 参数 | `STABILITY_WINDOW = 6`，`halfLife = 3` 次迁移 |

**为什么需要衰减项**：单纯的 0/1 标志无法表达「刚刚恢复」（应高于 idle、低于 monitoring），
而一个无衰减的阶段分数无法区分「稳定运行 1 小时」与「刚崩完」。

`stageWeight`：`idle 0.2 / monitoring 1.0 / crashed 0.0 / deciding 0.3 / stabilizing 0.7 / recovered 0.9`。

---

## 13. 风险评分 `riskScore`

| 项 | 内容 |
|---|---|
| 定义 | `risk = 0.5·recency + 0.3·experimental + 0.2·crashFrequency` |
| `recency` | `0.5^(ageHours / 72)`，半衰期 72 小时 |
| `experimental` | 命名是否带 experimental/beta/rc/canary/nightly/alpha |
| `crashFrequency` | `suspectHits / observations`（观测数 0 ⇒ 0） |
| 失效条件 | 解析失败的时间 ⇒ recency 记 0（不是不可判定，因为公式仍可算；但会拉低分数） |
| 复杂度 | O(1) |
| 验证 | `tests/unit/core.test.ts` |

**权重为什么这么分**：recency 是最强信号（时间局部性），experimental 次之（命名是强先验），
历史频率最弱（样本少、易过拟合）。

## 14. 样本充分度与显示位数

| 量 | 定义 | 用途 |
|---|---|---|
| `sampleConfidence` | `1 − 1/√n`（n ≥ 1），n ≤ 0 ⇒ 0 | 样本充分度降级指数；**不是覆盖概率** |

## 15. 模型失配检测（模型自己报告「我可能错了」）

这是本项目区别于普通指标看板的关键点：**每个模型都能报告自己被数据拒绝的证据**。

| 检测 | 落点 | 含义 |
|---|---|---|
| `cvObserved` vs 1 | `survival.ts` | 指数假设 CV 恒为 1，偏离即模型误配 |
| `hazardDirectionReliable` | `survival.ts` | 样本 < 9 时形状标准误足以翻转判定，方向只是提示 |
| `weibullShapeAtBound` | `survival.ts` | k 撞搜索上界 = 边界伪值，不是「形状真有一千」 |
| `converged` / `samples` | `markov.ts` | 平稳分布未收敛时不报数 |
| `unknown` 迁移计数 | `markov.ts` | 白名单外迁移被丢弃并如实计数 |
| `breachs` 点名 | `control-band.ts` | 哪一间隔越界被精确点名到序号 |

## 16. 参数调优哲学：不为调优而调优

本项目对参数的态度是**保守且可辩护**：

1. **每个参数都要有来历**：`d₂(2)=1.128` 来自统计质量控制常数表；
   `P75` 来自 cycle-3 实测；`3σ` 来自质量工程惯例；`halfLife=72h` 来自「用户通常在装完
   插件后几天内发现它坏了」的经验。
2. **阈值不收紧到噪声水平**：`control_bands.crash_rate` 用 warning 0.02 / alarm 0.05，
   不是 0.01——避免把噪声当趋势。
3. **样本少时自动降级显示**，而不是提高精度。
4. **边界伪值显式标注**，绝不伪装成估计值。

## 17. 复杂度账本

| 模型 | 复杂度 | 规模假设 | 说明 |
|---|---|---|---|
| `rankByRecency` | O(s log s) | s = 嫌疑插件数（几十量级） | 可忽略 |
| `markovAnalysis` | O(T + K·S²) | T=迁移数，S=6 | 线性于历史长度 |
| `intervalSurvival` | O(iters·n) | iters=100 | 轮廓似然二分 |
| `controlBand` | O(n) | n = 崩溃间隔数 | |
| `crashTrend` | O(n) | n = 间隔数 | |
| `crashIntervalStats` | O(n log n) | n ≤ 50 | 精确分位数 |
| `cusumChangePoint` | O(n log n) | n ≤ 50 | |
| `riskScore` | O(1) | — | |
| `stabilityScore` | O(1) | — | |

**复杂度预算**：`.cycles/config.yml` 的 `complexity_budget: 100`，且只统计
`src/` 下自写源码（排除 `lib/`、`runtime/`、`node_modules/`、`.tmp/`、`.cycles/`、`tests/`）。

## 18. 这张白皮书如何使用

1. **评审一个新模型**：对照本篇写「假设 / 定义 / 失效条件 / 复杂度 / 验证」五项，缺一项就别合并。
2. **排查「指标显示正常但系统在崩」**：先看是不是模型被数据拒绝（第 15 节），再看参数是否过紧。
3. **新功能选型**：先查有没有现成的模型能回答这个问题，而不是再加一个指标。
4. **写测试**：失效条件必须写成 `defined:false` 断言，而不是只测「正常输入」。

下一篇 `03-数据结构与算法选型.md` 讲这些模型靠什么数据结构跑起来。
