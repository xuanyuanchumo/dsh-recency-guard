# 09 · 整合研究：四方向 × 既有研究的合流

> 目的：把四个候选方向**放进**既有研究框架里研究，而不是孤立评判。
> 核心论点：**这四个方向不是四个独立特性，而是同一个问题的四种回答——
> 「如何把嫌疑排序从『最近时间戳』升级为『有证据强度的排序』」。**
>
> 孤立研究它们的三重失败：
> 1. 都绕不开「决策用纯时间戳、面板显示风险分」的**排序口径分裂**；
> 2. 都缺少**因子快照**，无法验证任何模型是否真有预测力；
> 3. 各自都以为自己在建新模型，其实项目**已有可复用的 machinery**。

## 1. 为什么必须合流：孤立研究的三重失败

### 1.1 失败一：都绕不开排序口径分裂

| 路径 | 用的排序 | 代码 |
|---|---|---|
| 决策关闭谁 | `rankByRecency`（纯时间戳） | `index.ts:797` → `recency.ts:121` |
| 面板展示风险 | `riskScore`（三因子） | `observability.ts:739` |

孤立研究每个方向时，都会得出「改进了排序精度」的结论。但**决策路径根本不消费这些改进**——
`publishDecisionOnCrash`（`index.ts:792`）读的是 `rankedSuspectsSync()`，
它调用 `rankByRecency`，不看 `riskScore`。四个方向改的模型若只进面板，等于改了个寂寞。

**合流结论**：任何方向的落地，都必须同时触碰 `rankByRecency` 或把它替换为 `riskScore` 的调用点。
这是四个方向共同的前置。

### 1.2 失败二：都缺少因子快照

方向一想知道「热更新五次 vs 三天前更新一次」哪个更该关；
方向二想知道「一小时内两次 vs 隔一天两次」证据强度差多少；
方向四想知道「共现是否真有预测力」。

**三者都需要同一份数据**：每个进入嫌疑面的插件，在每次决策时的各项因子值。
当前 `decision.json` 的 `suspects[]` 只有 `{bundle, version, lastChangeAt}`（`index.ts:826-830`），
没有因子分解。没有它，任何模型调参都是盲调。

**合流结论**：方向三不是第四个方向，而是**前三个方向的观测基础设施**。

### 1.3 失败三：都以为在建新模型，其实已有 machinery

| 方向以为自己在建 | 项目已有 | 代码 |
|---|---|---|
| 方向一：LRU-K 环形缓冲 | `RingBuffer<T>` 类（O(1) push） | `observability.ts:252` |
| 方向一：变更频率排序 | `rankByRecency` + `diffVersions`（install/update 事件） | `recency.ts:121,171` |
| 方向二：证据指数衰减 | `crashPressure`（EWMA of 0/1，H=5） | `observability.ts` |
| 方向二：间隔生存分析 | `intervalSurvival`（Weibull MLE） | `survival.ts:97` |
| 方向四：关系图 | `CapabilityGraph`（produces/consumes 双向可达） | `capability.ts:109` |

**合流结论**：每个方向都应先问「能不能复用已有的」，再谈「新建」。
方向一的「环形缓冲」就是现成的 `RingBuffer`；方向二的「衰减」已有 `crashPressure`。

## 2. 逐方向合流

### 2.1 方向一（LRU-K 变更频率）× 六主题

| 主题 | 合流后的理解 |
|---|---|
| **中文思维** | 对应「辨证施治」的**频率维度**——不只看「最近更新」，还看「更新得多不多」。这是把「时间局部性」从单点升级为分布。但要防「过犹不及」：频率高不等于有缺陷，`streak`（崩溃复现）才是缺陷证据。 |
| **数学模型** | 不是新模型，是 `riskScore` 的 recency 因子**从一维升级为二维**。现有 `recency = 0.5^(age/72)` 只反映「最近一次变更距今多久」；频率维度反映「变更事件密度」。两者可合成 `recency2 = recency × (1 + α·frequency)`。 |
| **数据结构** | **复用 `RingBuffer`**（`observability.ts:252`）。但当前它用于窗口统计（`observability.ts:288`），不是「每个插件一个变更事件缓冲」。需要新增 `Map<plugin, RingBuffer<timestamp>>`，O(1) 更新。**LRU-K 的语义错配**（访问 vs 变更）见 08，合流后应改名为「变更频率因子」。 |
| **语言范式** | 复用 Rust 的「无 NaN 比较」纪律——不可解析的时间戳不能进缓冲；复用纯函数纪律——频率计算必须纯函数可测。 |
| **验证** | 需要变异自证：把频率因子权重设为 0，断言排序退化为纯时间戳；把缓冲长度设为 0，断言不可判定（`defined:false`）。 |
| **应用场景** | 泛化性高——任何「最近变更是第一嫌疑人」的领域都适用（IDE 插件、CI 依赖、K8s 镜像）。但需要「变更事件可观测」这一前提。 |

**合流后的关键判断**：方向一的价值不在 LRU-K，在于「recency 因子缺频率维度」。
而它要生效，**必须配合排序口径统一**——否则改了 `riskScore`，决策路径仍用 `rankByRecency`。

### 2.2 方向二（证据年龄衰减）× 六主题

| 主题 | 合流后的理解 |
|---|---|
| **中文思维** | 对应「过犹不及」——久远的证据不该和新鲜证据同等权重；也对应「实事求是」——不能把「三个月前崩过」当成「现在仍在崩」。但必须守住「可用性优先」：环境未变时，间隔一天的两次崩溃**仍是确定性缺陷**。 |
| **数学模型** | 与 `crashPressure`（EWMA of 0/1 启动信号）**同族但作用对象不同**——`crashPressure` 作用于启动序列，方向二作用于崩溃序列。**更优做法是复用 `intervalSurvival` 的 `hazardDirection`**：`k<0.9`（成簇）说明崩溃有连带，应更积极；`k≈1`（泊松）说明随机，应更保守。这比自造指数衰减更可解释、已有实现、已有测试。 |
| **数据结构** | 复用 journal 的崩溃时间戳序列（`readJournalSync(1000)`，`index.ts:619`）。不需要新结构。 |
| **语言范式** | 复用数值稳定性纪律——`survival.ts` 的 log-space 二分、`logSumExp`。若做衰减，`w_i = e^(−λΔt_i)` 的数值稳定性要按同一纪律处理。 |
| **验证** | 变异自证：把 λ 设为 0，断言退化为纯计数；把 λ 设为极大，断言所有证据归零。契约测试：λ 必须有标定依据（项目纪律「参数要有来历」）。 |
| **应用场景** | 泛化性中——依赖「崩溃间隔有意义」。在批处理、定时任务场景，间隔的语义不同。 |

**合流后的关键判断**：方向二的直觉对（时间有信息），但**实现方向（指数衰减）与已有生存模型重复**。
合流后应改为「用 `intervalSurvival` 的分布形态驱动证据强度」，而非自造衰减。

### 2.3 方向三（因子快照）× 六主题

| 主题 | 合流后的理解 |
|---|---|
| **中文思维** | 对应「实事求是」与「白盒透明」——决策的理由必须落盘。这是本项目「每个读数带 formula/inputs」纪律在**决策层**的落地。 |
| **数学模型** | 不是模型，是**模型的输入/输出契约**。它让方向一/二/四的模型可以被离线回放验证。 |
| **数据结构** | 扩展 `decision.json` 的 `suspects[]` 条目（向后兼容）。`guardExpression` 只读 `disable`（`decision.ts:153`），不受影响。 |
| **语言范式** | TypeScript「类型即契约」——`Decision` 接口扩展后，老版本读新字段应优雅降级（只读 disable）。 |
| **验证** | 契约测试：快照字段完整；变异自证：删掉因子字段，断言离线回放工具报「证据不足」。 |
| **应用场景** | 泛化性最高——任何「需要事后归因」的自动决策系统都需要决策快照。 |

**合流后的关键判断**：方向三是**前三个方向的前置**。没有它，方向一/二/四无法验证。
它的优先级应该是 P0，而不是与其余并列。

### 2.4 方向四（共现加权）× 六主题

| 主题 | 合流后的理解 |
|---|---|
| **中文思维** | 对应「系统观/整体观」——插件不是孤立的，崩溃可能在依赖链上传染。但必须守住「适可而止」：官方实验插件的观测数据**只用于归因与辅助加权**，绝不用于关闭官方组件本身。 |
| **数学模型** | 需要新的「共现因子」。可并入 `riskScore` 作为第四因子（当前权重 0.5/0.3/0.2）。但**共现 ≠ 因果**——官方插件崩溃时非官方插件可能只是「在场」，共现会**增加误伤**。 |
| **数据结构** | **数据基础不存在**。`official-observe.ts:28-32` 只有 `{bundle, version, enabled}`；`declaredDependenciesSync`（`store.ts:743`）是 profile 声明的依赖列表，**不是运行时依赖图**。`CapabilityGraph` 是插件**内部**能力，不是插件间依赖。需要先采集依赖关系数据。 |
| **语言范式** | 复用声明式纪律——依赖关系应该声明式表达，而不是运行时猜。 |
| **验证** | 必须先有方向三的快照，才能离线回放验证「共现是否真有预测力」。否则违反「先验证假设再行动」。 |
| **应用场景** | 泛化性依赖「有依赖图」——CI 依赖图、K8s 依赖图有；简单插件系统没有。 |

**合流后的关键判断**：方向四的**数据基础不存在**，优先级最低。
但它是四方向里唯一真正利用「官方实验插件观测数据」的方向——如果不做它，
那批数据就真的浪费了。所以它值得做，但要用数据驱动的方式做。

## 3. 跨方向的三个共同发现（合流的核心产出）

### 3.1 共同阻塞：排序口径分裂

四个方向都改的是「排序的精度」，但决策路径读的是 `rankByRecency`。
**不修这个分裂，四个方向全部空转。**

修法（分阶段）：

| 阶段 | 做法 | 风险 |
|---|---|---|
| 短期 | `decision.json` 的 `suspects[]` 同时记录 `riskScore` 与 `rank`，让面板能解释 | 低（只加字段） |
| 中期 | 确定性证据（唯一嫌疑）仍用 `rankByRecency`；概率性证据改用 `riskScore` 排序头号 | 中（改决策路径） |
| 长期 | 统一排序口径，`rankByRecency` 退化为 `riskScore` 的 recency 因子输入 | 高（大重构） |

### 3.2 共同依赖：因子快照

方向一要频率因子值、方向二要证据年龄、方向四要共现标记——**都需要方向三的快照**。
方向三不是第四个方向，是**前三个的观测基础设施**。

### 3.3 共同纪律：复用优于新建

| 方向 | 新建什么 | 已有什么 | 结论 |
|---|---|---|---|
| ① | LRU-K 环形缓冲 | `RingBuffer` | 复用 |
| ② | 证据指数衰减 | `crashPressure` / `intervalSurvival` | 复用生存模型 |
| ③ | 决策快照 | `MetricMeta` 白盒契约 | 落地契约 |
| ④ | 共现加权 | `CapabilityGraph`（但不适用） | 需新采集 |

## 4. 方向间的张力与调和

### 4.1 方向一 × 方向二：频率 vs 衰减

表面冲突：方向一说「变更越频繁越可疑」（时间越近越可疑），
方向二说「崩溃证据越久远越弱」（时间越久越不可信）。
两者都作用于时间，但**作用于不同对象**：

| | 作用对象 | 时间方向 | 语义 |
|---|---|---|---|
| 方向一 | **变更事件**（因） | 越近越可疑 | 先验概率：最近变更更可能引入缺陷 |
| 方向二 | **崩溃证据**（果） | 越久越弱 | 似然：久远的崩溃不代表现在仍有缺陷 |

**调和方式**：用贝叶斯框架分离两通道。
`P(plugin | crash) ∝ P(crash | plugin) · P(plugin)`，
其中 `P(plugin)` 由方向一（变更频率）提供先验，
`P(crash | plugin)` 由方向二（证据衰减）提供似然。

**关键前提**：必须用方向三的快照把两通道的因子**分开记录**，否则会错误合并。
这正是方向三优先级最高的理由。

### 4.2 方向三 × 其余：证据先于模型

方向三是观测基础设施，方向一/二/四是模型假设。
**没有观测，模型无法验证。** 这条依赖链决定了优先级。

### 4.3 方向四 × 官方纪律

方向四想用官方实验插件的崩溃数据加权非官方插件。这**不违反**「不关闭官方组件」，
但有微妙风险：若把官方插件的崩溃错误归因给非官方插件，会**关闭错误的插件**。

**调和方式**：
- 共现因子权重不超过 0.1（远低于 recency 的 0.5）；
- 只在「官方实验插件在崩溃窗口内确实变更过」时触发（比「活跃」严格）；
- 写进注释：「官方实验插件观测数据只用于归因展示与非官方插件辅助加权，
  绝不用于决定关闭官方组件本身」。

## 5. 统一研究问题框架

把 07 的 RQ 与四个方向合流后，研究问题不再是四个孤立问题，而是一个层次结构：

```
RQ0（基础设施）：决策理由能否落盘、能否离线回放？   ← 方向三
   │
   ├── RQ1（归因）：如何把排序从时间戳升级为证据强度？  ← 方向一 + 方向四
   │     ├─ 方向一：变更频率因子（先验）
   │     └─ 方向四：共现因子（弱先验，需依赖数据）
   │
   ├── RQ2（误伤）：如何区分「持续在崩」与「偶然崩过」？ ← 方向二
   │     └─ 用 intervalSurvival 分布形态，而非指数衰减
   │
   └── RQ3（信号）：能否在崩溃前预警？               ← 07 已有
         └─ 预防性健康指标（只预警不行动）
```

**RQ0 必须先做**——没有它，RQ1/RQ2/RQ4 无法验证。

## 8. 合流后的三条工作纪律

1. **先修分裂，再谈模型**——排序口径统一是四个方向的公共前置。
2. **先有快照，再调参数**——因子快照是所有模型验证的基础设施。
3. **先问复用，再谈新建**——每个方向先对照项目已有 machinery，避免重复造轮子。

这三条纪律，是「把四个方向放一起研究」的直接产物。
孤立研究时，每条纪律都显得是「额外的约束」；
合流后，它们是**让四个方向真正生效的最小必要条件**。
