# 01 · 中文思维与故障守护

> 目的：把 `dsh-recency-guard` 的设计直觉，显式翻译成可讨论、可反驳的命题。
> 纪律：**每个映射都必须有代码落点**。落不了地的比喻，会从「启发」退化成「装饰」，
> 因此文末给出「映射强度分级」与「反模式」两节来约束这种退化。

## 0. 为什么先谈思维，再谈数学

本项目的数学模型（马尔可夫链、Weibull、控制带）回答的是「**量怎么算**」。
但真正决定成败的是三个更上游的问题：

1. **什么时候该动手**（过早动手误伤无辜，过晚动手崩溃循环）——这是价值判断；
2. **该动谁**（最近更新的一定是元凶吗）——这是归因判断；
3. **做错了怎么退**（关掉的插件能不能安全放回来）——这是边界判断。

这三个判断，纯数学给不出答案，因为它们涉及**取舍的优先级**。中文思维里恰好有一套
被几千年实践打磨过的取舍语言：预防、辨证、中庸、灰度、有备无患、适可而止。
本篇做的是把这套语言「转译」成工程机制，而不是拿它做修辞。

## 1. 上医治未病 —— 预防优于救火

**本义**：最高明的医生在病未发作前就干预（《黄帝内经》"圣人不治已病治未病"）。

**工程转译**：守护的大部分价值不在崩溃后，而在崩溃**前**的可逆性。

| 机制 | 落点 | 说明 |
|---|---|---|
| 变更前配置快照 | `patch.ts` / 时间线备份 | 插件更新前把旧配置存为 `<版本>@<时刻>.json`，默认每插件保留 5 份 |
| 变更可回滚 | `patch-scalar.ts` 校验后提交 + 原子回滚 + pristine 备份 | 发射正确还不够，接缝（别人手写的行）才是风险 |
| 两阶段提交 | `recovery-policy.ts:133 DecisionPhase`（reconcile 在 :260 `reconcilePrepared`） | `prepared` → `quarantined`，中途死亡则下次启动按磁盘对账 |
| 启动前拦截 | `decision.ts:139` | 坏插件的 `disabled` 表达式在 **import 之前**求值 |

**验证**：`tests/unit/versioned-backup.test.ts`（备份与恢复）、`tests/unit/patch-safety.test.ts`
（校验/原子/回滚）。

**失效风险**：预防措施本身会增加启动开销。因此 `performance-baseline.md` 把
「同步启动 IO 次数 ≤ 6」列为硬阈值——**预防不能以拖慢每一次启动为代价**。

## 2. 防微杜渐 —— 别等塌了才响应

**本义**：在苗头刚出现时就处理，避免从小错酿成大祸。

**工程转译**：崩溃信号要**多通道**，且要捕捉最早期、最微弱的信号。

本项目真实踩过的坑（v0.12.1）：崩溃信号此前**只有哨兵文件**，而哨兵写在
`process.on('exit')` 里——`SIGKILL` / OOM killer / 断电 / 原生段错误**根本不运行 exit 处理器**。
结果是：强杀后 `bootMarker` 残留（pid 已死）而 `crashSeq` 仍是 0，下一次启动报
「未发现上次崩溃」，**崩溃循环失去升级依据，永远停在「关 0 个」**。

补的第二条通道（`recovery-policy.ts:61 classifyAbnormalExit`）给出四种结局：

| 结局 | 判据 | 处理 |
|---|---|---|
| `clean` | 无残留 / 有哨兵 | 归零 |
| `self-reload` | 残留 pid == 本进程（热重载） | 归零 + 留痕（**不可误报「另一个实例」**） |
| `concurrent` | 残留 pid 仍活着且不是自己 | 归零 + 留痕 |
| `abnormal` | 残留 pid 已死 | 计数 +1，达阈值才动手 |

**验证**：真机两次强杀：`1/2 轮 act=false` → `2/2 轮 act=true 关闭 1 个`；
单测 `tests/unit/core.test.ts` 钉住 `classifyAbnormalExit` 四分支。

**失效风险**：异常终止按**概率性证据**处理（残留标记也可由人为杀进程产生）。
这正是「防微杜渐」与「草木皆兵」的分界线——用 `confirmRounds` 把一次信号压成
「先观察一轮」。

## 3. 辨证施治 —— 归因要分层，不可一刀切

**本义**：中医辨证（阴阳、表里、寒热、虚实）强调同病异治、异病同治，先分类再施治。

**工程转译**：崩溃的「嫌疑人」必须分层，不同层的处理策略**不可互换**。

| 分层 | 判据 | 处理策略 | 代码 |
|---|---|---|---|
| 官方稳定包 `@deepseek-ai/*`（非实验） | 同源、用户未主动装 | 永不自动关闭 | `recency.ts:69 isOfficial` |
| 官方实验包 `@deepseek-ai/dsh-experimental-*` | 官方 scope + 实验命名 | **只观测不关闭**（`official-observe`） | `recency.ts:65 isOfficialExperimental` |
| 第三方/普通实验包 | 非官方、已安装已启用 | 可自动关闭 | `recency.ts:92 isSuspectClass` |
| 守护自身 | 名字 == `dsh-recency-guard` | 永不关闭（关掉等于拆掉恢复机制） | `recency.ts:90 GUARD_PACKAGE` |

多因子风险评分是「辨证」的量化实现（`lifecycle.ts:373 riskScore`）：

```
risk = 0.5·recency + 0.3·experimental + 0.2·crashFrequency
recency      = 0.5^(ageHours / 72)     （半衰期 72 小时）
experimental = 命名是否带 experimental/beta/rc/canary/...
crashFrequency = 历史嫌疑次数 / 历史观察次数
```

**为什么 recency 权重最高（0.5）**：时间局部性是最强信号——用户通常在装完插件后几天内
发现它坏了。experimental 次之（命名是强先验），历史频率最弱（样本少、易过拟合）。

**验证**：`tests/unit/official-experimental.test.ts`（分层判据）、
`tests/unit/core.test.ts`（风险评分边界）。

**失效风险**：`isExperimentalName` 用字符串 hints 匹配，`@deepseek-ai/dsh-web` 这类
稳定包可能被误判——因此要求**官方 scope 与实验命名同时满足**才进观测通道。
判据保守是刻意的：宁可漏观测，不可把官方组件当嫌疑。

## 4. 标本兼治 —— 止血与除根并行

**本义**：急则治其标（先稳住），缓则治其本（再找根因）。

**工程转译**：守护必须同时回答两个问题，缺一不可。

- **标（让宿主先活下来）**：关闭最近更新的嫌疑插件 → `recovery-policy.ts` 的
  `recover()` → 重启后 profile 能启动。
- **本（留下可归因的证据）**：崩溃时发布决策文件 + 指针文件（`decision.ts`）、
  journal 记录、归档清单（`archive.ts`）、时间线备份。

**v0.12.1 的真实案例**：只止血不治本，会把「关了嫌疑 → 又死一次（无哨兵）」读成
「崩溃已过」⇒ 把插件全部恢复 ⇒ 崩溃循环原地复活。修复是把判据从「有没有哨兵」
改成「上一轮是不是**干净退出**」（`recovery-policy.ts:shouldRestoreAfterBoot`，
用 5 条单测钉住）。

**验证**：`tests/unit/recovery-policy.test.ts`；`.cycles/flow-history.jsonl` 里可查真实事件链。

## 5. 过犹不及 / 中庸 —— 阈值要「够用就好」

**本义**：做事过了头和没做到一样不好（《论语》"过犹不及"）。

**工程转译**：灵敏度与误伤率是零和的，设计目标是**在阈值处取得平衡**，而非追求极端。

| 平衡 | 落点 | 中庸的做法 |
|---|---|---|
| 崩溃率控制带 | `.cycles/config.yml` `control_bands.crash_rate` | warning 0.02 / alarm 0.05——不是 0.01，避免噪声触发 |
| 稳定性分 | `.cycles/config.yml` `control_bands.stability_score` | warning 0.6 / alarm 0.3 |
| 确认轮数 | `confirmRounds`（默认 2） | 确定性证据 1 轮即动，概率性证据 2 轮才动 |
| 控制带宽度 | `control-band.ts` x̄±3σ̂ | 3σ 是传统质量工程的经验值，不随意收紧 |
| 置信降级 | `observability.ts:108 sampleConfidence` | 小样本不报满位数，避免伪精度 |

**CUSUM 基准为什么是 P75 不是中位数**（`observability.ts` 头注，cycle-3 实测）：
中位数定义上让一半样本低于基准，容差后几乎无法累计证据——检测器对真实变化
**结构性失明**。P75 之下只有 25% 样本，只有持续显著变密才推得过阈值。
这是「中庸」的反面教材：**阈值选错，会让系统对真实问题天生失明**。

**失效风险**：`stabilityScore` 用 `stageWeight × exp(-λ·recentTransitions)` 的衰减，
参数 `halfLife=3` 是经验值。它回答的是「状态是否在震荡」，不是崩溃率本身。

## 6. 灰度 / 试错 —— 渐进式隔离，可退可进

**本义**：不一次性全量切换，先小范围试探。

**工程转译**：关闭动作是**渐进**的，且每步可逆。

```
第 1 次崩溃 → 关最近更新的 1 个
第 2 次崩溃 → 关最近更新的 2 个
...
稳定后 → 除首要嫌疑外，其余被关配置自动恢复
```

（`recency.ts:163 pickSuspects` 的 `n` 随崩溃次数递增）

可逆性的三件套：

| 机制 | 落点 | 作用 |
|---|---|---|
| 时间线备份 | 备份目录按版本分层 | 升级前后配置可逐版对账 |
| 手动放行 | `reenable` action | 用户确认安全后恢复单个插件（诚实失败：管理器拒绝则如实报失败） |
| CLI 逃生通道 | `bin/rescue.mjs` | 宿主起不来时离线读取守护产物（零依赖、只读、退出码 2=有未恢复崩溃） |

**失效风险**：v0.11.2 修过一个「假成功」：`reenable` 曾无条件返回 `reenabled: true`，
而管理器实际返回 `application: 'failed'`。修法是**只有真的 applied 才算成功**。
「灰度」若无诚实的结果反馈，就只是把按钮画得好看。

## 7. 庖丁解牛 —— 分层，让每一层可独立穷举

**本义**：顺着筋骨缝隙下刀，"以无厚入有间"，省力而精准。

**工程转译**：复杂度超预算的模块，按「职责缝隙」切开，让每一层都能被独立测试。

真实案例（v0.7）：`patch.ts` 膨胀到复杂度 142（预算 100）。按标量 / 文档 / 行寻址
三层切开：`patch-scalar.ts` / `patch-yaml.ts` / `patch.ts`（门面），各层可独立穷举测试。

其他同源实践：

| 拆分 | 原因 |
|---|---|
| `observability.ts` → `survival.ts` / `control-band.ts` | 「一个数学模型一个文件」，单测与实现同址 |
| `index.ts` → `abnormal-boot.ts` | 启动判定有三个身份（信号源/留痕/计数），热点推到 117 越预算 |
| `graph-model.ts` → `minimap-model.ts` | graph-model 117→101；且**刻意各读 `LAYOUT`** 以避免循环依赖 |

**验证**：`.cycles/config.yml` 的 `complexity_budget: 100` 由 band-detector 计分；
`scripts/gen-guard-patch.mjs` 等工具佐证分层。

## 8. 运筹帷幄 —— 决策要在正确的时机发布

**本义**：谋定而后动，先算后战。

**工程转译**：**决策必须在崩溃的那一刻发布**，而不是等下次启动再算。

原因（`docs/agents/design.md`）：Loader 并发创建各行，等下次启动再写决策会与
嫌疑插件那一行的求值**竞态**（v0.1 实测）。

但表达式作用域只有 `ctx` 和 `process`，**拿不到分区键**（分区键由插件按
`profileContext.cwd` 算出）。解法是「指针文件」这座桥（`decision.ts:105 writePointer`）：
profile 目录下放 `.recency-guard/current.json`，指向「本工作区当前分区」的决策文件。

**为什么宁可「误指」也不要「指不到」**：

- 指针缺失/不合法 ⇒ 表达式一律返回 `false`（放行）——**宁可过放行，不可过拦截**；
- 误指 ⇒ 只多关一个可能无关的插件；
- 指不到 ⇒ 全部放行 ⇒ 回到崩溃重演（破坏恢复能力）。

**失效风险**：并发工作区会串扰指针（指针在 profile 目录是全局一份）。这是**已知**的
诚实边界，写入 `decision.ts` 头注。

## 9. 纲举目张 —— 抓住单一真相源

**本义**：提起网的总绳，网眼自然张开。

**工程转译**：能力/事实的关系，不要散落在工具注册、状态、面板、日志四处。

`capability.ts` 把「能力」建模成有向图：`capability --produces--> fact <--consumes-- capability`。
索引据此做**双向可达性**检查：

- 产出无人消费 → 「过度生产」（白盒可见的浪费）
- 消费无人生产 → 「消费断链」（功能不连通）
- 声明了却没实例化 → 「注册面缺口」

纪律：**索引是投影，不是第二真相源**（`capability.ts` 头注）。真相在注册处，
由契约测试做双向比对（`capability-specs.ts:445 verifyCapabilityContract`）。

**验证**：`tests/contract/capability.test.ts`（100% 覆盖目标）。

---

## 10. 有备无患 —— 永远留一条不依赖宿主的退路

**本义**：事先有准备，就不怕突发。

**工程转译**：当守护机制本身失效时，要有**不依赖宿主**的读路径。

| 备份 | 落点 |
|---|---|
| CLI 逃生通道 | `bin/rescue.mjs`：`status\|history\|decision\|archives`，零依赖、只读 |
| 语义化退出码 | 退出码 2 = 有未恢复崩溃，供脚本联动 |
| 时间线备份 | 更新前配置快照，默认每插件 5 份 |
| 归档留档 | `archive.ts:86 archiveAndReset`：manifest **先读后搬**，搬走 + 留档 |

**失效风险**：归档重置后不继承旧结论——「reset 后旧结论作废」是刻意的语义，
避免界面继续显示上一轮的 `crashed`。

## 11. 不以规矩不能成方圆 —— 用状态机白名单

**本义**：没有圆规和曲尺，就画不出方与圆。

**工程转译**：把「不可能的状态」变成**根本无法表示**。

散落的标志位（`enabled/crashed/recovering/stabilized`）会产生不可能的组合
（既 crashed 又 stabilized），而这些组合在真实运行中确实会发生。状态机
（`lifecycle.ts:80 ALLOWED`）显式写出合法迁移：

```
idle → monitoring → crashed → deciding → stabilizing → recovered → monitoring/idle
```

不变式：只有 `deciding` 可发「关闭插件」动作；`crashed` 只能经 `deciding` 离开；
非法迁移返回 `false` 不抛异常（观测设施不拖垮守护流程），但**留痕**到
`rejectedTransitions`。

`reset()` 是治理复位：绕过白名单把阶段强制拉回 `idle`，并写 `forced: true` 留痕。

**验证**：`tests/unit/core.test.ts` 穷举迁移表。

## 12. 格物致知 / 知行合一 —— 证明要走到真实路径

**本义**：探究事物原理才能获得真知；认识与实践要统一。

**工程转译**：测试必须走**真实数据流**，不能停在 mock 上。

真实案例（v0.12）：命令窗口的展示投影 `presentCall/presentResult/output.presentationMeta`
**写好了却没接进 `defineTool`**——宿主因此落回通用回退卡片。反漂移用了**双门**：

1. **契约源码门**：源码里必须有接线；
2. **宿主行为门**：走宿主同一条数据流 `execute → presentationMeta → presentResult`，
   含旧记录回放的诚实降级。

**变异自证**：把缺陷写回源码（例如 `setPointerCapture?.(id)` 裸调用），断言必须 FAIL，
再修回变绿。只有「会响的测试」才算测试。

**验证**：`tests/client/minimap-gesture.test.ts`（源码门 + 变异自证）、
`tests/host/revision-source.test.ts`（端到端门）。

## 13. 实事求是 —— 诚实边界：无数据 ≠ 零

**本义**：从实际情况出发，不夸大不缩小。

**工程转译**：写死在类型里的三条诚实边界（`observability.ts` 头注）：

1. **无数据 ⇒ 不给分**（`value: null` + `defined: false`），绝不给 0；
2. **分母为 0 ⇒ 比率不可判定**（不是 0）；
3. **颜色/评分不是唯一通道**：每个读数带可读文本 `label`。

`undefinedMetric` / `definedMetric` 两个构造器独占保证 `value` 与 `defined` 一致，
上层不得手写字面量——否则会出现「有 reason 但有值」的伪状态。

**这条纪律的价值**：v0.12.1 的崩溃信号补通道，正是因为旧逻辑把「没有哨兵」
**代理**成「活过了启动」，而代理在第二通道下破裂，导致亲手拆掉刚建立的隔离。
**代理一旦破裂，诚实边界就是最后的防线。**

## 14. 适可而止 —— 知道什么不该做

**本义**：做到适当程度就停止。

**工程转译**：守护有能力边界，越界比缺能力更危险。

| 不该做 | 原因 | 代码证据 |
|---|---|---|
| 关闭官方稳定包 | 关掉官方组件等于卸掉宿主半边 | `recency.ts:69 isOfficial` |
| 关闭官方实验包 | 官方明示实验场，风险不可接受 | `recency.ts:65 isOfficialExperimental` |
| 关闭守护自身 | 关掉等于拆掉恢复机制 | `recency.ts:90 GUARD_PACKAGE` |
| 把 `recovering && !crashedLastRun` 当「崩溃已过」 | 代理在第二通道下破裂 | `recovery-policy.ts:shouldRestoreAfterBoot` |

**失效风险**：v0.5.0 沙箱实测，`recover` 曾把守护自己关掉（它是 profile 里唯一的
非官方插件）——两条路径必须共享同一不变式。

## 15. 阴阳平衡 —— fail-open 与 fail-closed 的取舍

**本义**：对立双方互相依存、动态平衡。

**工程转译**：守护行表达式是典型的二元取舍。

| 取向 | 含义 | 本项目选择 |
|---|---|---|
| fail-closed（拦死） | 判不了就全部拦截 | ❌ 会把 profile 锁死在插件之外 |
| fail-open（放行） | 判不了就放行 | ✅ `guardExpression` 任何一步失败返回 `false` |

但「恢复已关闭插件」的路径是 **fail-closed**：`shouldRestoreAfterBoot` 要求
`exitClass === 'clean'`，绝不把异常终止当干净。

**所以本项目是「拦截时 fail-open、恢复时 fail-closed」**——这是阴阳的具体形态：
**保命时宽松，放行时严格**。

## 16. 映射强度分级（诚实标注）

为避免「比喻滥用」，把上述映射按证据强度分三级：

| 强度 | 判据 | 本篇中的映射 |
|---|---|---|
| **强** | 直接对应代码机制 + 有测试 | 上医治未病、防微杜渐、标本兼治、运筹帷幄、有备无患、不以规矩、实事求是、适可而止、阴阳平衡 |
| **中** | 机制存在但对应较抽象，属设计哲学 | 辨证施治（分层）、过犹不及（阈值）、灰度（渐进隔离）、纲举目张（单一真相源）、格物致知（变异自证） |
| **弱** | 借用修辞，无独立机制 | 庖丁解牛（其实是复杂度治理）、愚公移山（技术债清理）——仅作叙事框架 |

## 17. 反模式（踩过的坑，写下来防再犯）

1. **把「最近更新」当「元凶」** —— 相关性 ≠ 因果性。所以有 `confirmRounds` 与
   `crashFrequency` 因子，且偶发崩溃不误伤。
2. **把「没有崩溃记录」当「崩溃率 0」** —— 由 `Metric<T>` 类型杜绝。
3. **把「热重载」当「另一个实例」** —— `self-reload` 分支专门防假归因。
4. **把「存在哨兵」当「崩溃循环在升级」** —— 第二通道下哨兵缺席也计异常。
5. **把「面板显示成功」当「动作真的生效」** —— v0.11.2 的 `reenable` 假成功。
6. **把「指标有值」当「结论可靠」** —— `hazardDirectionReliable`、`shapeAtBound`、
   `defined:false` 显式标注。
7. **把「比喻」当「设计依据」** —— 见上节强度分级。

## 18. 小结：中文思维给这套系统的三句话

1. **预防优于救火**——可逆性是守护的第一资产（备份、原子写、两阶段提交）。
2. **取证先于行动**——确定性证据立即动，概率性证据数轮确认（辨证 + 中庸）。
3. **退路永远留着**——拦截时 fail-open，恢复时 fail-closed，CLI 可离线读盘（有备无患）。

这三句话不是口号，它们各自对应一组代码、一组测试、一组失效条件。
下一篇 `02-数学模型白皮书.md` 会把它们翻译成可计算的量。
