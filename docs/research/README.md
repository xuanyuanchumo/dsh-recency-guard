# 研究文档集 · dsh-recency-guard

> 目标读者：想把一个「崩溃恢复守护」插件，从「能跑」推进到「可证明、可泛化、可长期自治」的工程师与研究者。
> 写作语言：中文。每个概念都必须能落到代码或测试上；落不了地的比喻，一律删除。

## 0. 这个项目在做什么（一句话）

DSH（DeepSeek Harness）加载第三方/实验性插件时，一个坏插件会把宿主拖崩。`dsh-recency-guard`
在**崩溃的那一刻**记录「谁最可疑」，并在**下一次启动、坏插件被 import 之前**把它挡在门外；
反复崩溃时逐个扩大关闭数量，稳定后自动恢复其余插件的配置。它不预测未来，只做三件事：
**记录事实 → 分级取证 → 保守行动**。

当前版本 `v0.12.1`，已具备：生命周期状态机、崩溃置信分级、两阶段提交、诚实边界指标体系、
马尔可夫链 / 休哈特控制带 / Weibull 生存分析、能力图双向可达性、面板可交互图谱与 CLI 逃生通道。

## 1. 这套文档回答什么

现有文档（`README.md`、`docs/agents/*.md`）回答「**做了什么、怎么做的**」。
本套文档回答三个更上游的问题：

1. **为什么这样设计是对的**——用中文思维的本体论（预防、辨证、中庸、灰度……）把设计直觉
   显式化，变成可讨论、可反驳的命题，而不是「我觉得」。
2. **它背后是什么数学**——每个模型/数据结构/算法的假设、定义式、失效条件、复杂度、验证方法，
   以及它**不能**回答什么。
3. **怎么继续做下去**——研究假设、实验设计、验证体系、应用场景与迭代路线。

## 3. 三根主线（贯穿全部文档）

```
现象 ──▶ 模型 ──▶ 决策 ──▶ 验证 ──▶ 工程化
```

- **现象**：崩溃、更新、异常退出。来自 `sentinel.ts` / `abnormal-boot.ts` / `recency.ts`。
- **模型**：把现象变成可比较、可判定的量。见 `02-数学模型白皮书.md`。
- **决策**：在「宁可漏拦、不可把 profile 锁死」的约束下取一个动作。见 `recovery-policy.ts` /
  `decision.ts`。
- **验证**：每个命题都要能被测试或变异实验证伪。见 `05-验证与可证伪体系.md`。
- **工程化**：复杂度预算、依赖代际对齐、确定性布局、同步崩溃路径。见 `03` / `04` / `07`。

## 6. 阅读时的三个自检问题

读任何一篇，请随手问：

1. **它落在哪行代码？**——落不了地的，是文学不是工程。
2. **它在哪条测试里被证伪？**——没有反例的命题，是信仰不是知识。
3. **它失效的条件是什么？**——没有失效条件的模型，是万能胶也是黑盒。

这三个问题的答案，就是这套文档存在的全部理由。
