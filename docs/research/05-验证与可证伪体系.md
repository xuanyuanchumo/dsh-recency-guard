# 05 · 验证与可证伪体系

> 目的：本项目的每一条设计主张，都必须能被**证伪**。本篇讲它怎么做到，
> 以及**怎么识别「看起来绿、实际假绿」**。
>
> 元规则（写在 `.cycles/config.yml` 与 `docs/agents/verification.md`）：
> **「无法评估」≠「通过」**；指标不可判定时为 `null`（`Metric.defined=false`），
> 绝不把「无数据」当「零」。

## 0. 为什么验证是第一优先

本项目有两条血泪教训，都指向同一个结论：

1. **命令窗口展示投影写好了却没接进 `defineTool`**——宿主落回通用回退卡片，
   直到宿主行为门才发现（v0.12）。
2. **`reenable` 无条件返回 `reenabled: true`**——管理器实际返回 `application: 'failed'`，
   面板显示成功而插件仍关闭（v0.11.2）。

两条都是「**没有测试走真实路径**」导致的。因此本项目的验证哲学是：
**测试必须走到真实数据流，能响的测试才算测试。**

---

## 1. 四层测试金字塔

`.cycles/config.yml` 的 `layers`：

| 层 | 模式 | 覆盖目标 | 职责 |
|---|---|---|---|
| Core | `tests/unit/**/*.test.ts` | 90% | 纯逻辑：状态机、隔离、数学模型、patch 安全 |
| Host | `tests/host/**/*.test.ts` | 85% | 插件入口、守护流程、服务与事件 |
| Client | `tests/client/**/*.test.ts` | 80% | 面板与图谱的纯函数部分 |
| Contract | `tests/contract/**/*.test.ts` | **100%** | 能力索引 ↔ 注册处双向比对（漏一条就是真缺口） |

**为什么契约层要 100%**：契约测试不是「覆盖率」，是**双向比对**——
声明了却没注册、注册了却没声明，都是真实缺口。这类缺口不会让任何功能失败，
只会让「能力清单」变成谎言。

**四层分离的意义**：Core 层**不依赖宿主**，因此数学模型可以被 `tsx` 直接驱动，
不需要起浏览器、不需要装真实插件。这是「测试成本决定反馈速度」的体现。

---

## 2. 契约测试：索引是投影，不是真相

### 2.1 能力契约

`capability-specs.ts:445 verifyCapabilityContract` 做双向比对：

- 能力清单（`CAPABILITY_SPECS`）↔ 注册处（工具注册、事件发射、状态写入）；
- 工具侧细化到 **action**：声明了不存在的 action、注册了没人声明的 action，都是缺口；
- **注入面双向核对**：声明的 `hostServices` 必须真的在 inject 面上；inject 面上的服务
  必须被至少一个能力声明（否则是无人解释的注入）。

### 2.2 宿主真实事实见证（依赖代际对齐）

v0.12 新增**「以宿主真实事实为见证」的契约门 11 条**：

- 逐 peer 用 `runtime/`（从 app.asar 解出）的装机版本做 `semver.satisfies` 判定；
- devDep == 装机版本断言。

**为什么**：桌面端用 `link:` 直连源码从不走兼容闸门，所以「peer 范围过窄」的洞
在本机完全不可见。只有拿宿主真实装机版本做见证，才能发现。

## 3. 源码门：把「不得出现」写成断言

### 3.1 案例：小地图手势

v0.12.1 修复「小地图点击无反应」：`setPointerCapture?.(id)` 排在 `onNavigate(...)`
**之前**，而可选链只保护「方法不存在」，**不保护方法抛异常**。浏览器在 pointerId
失效时按规范抛 `NotFoundError` ⇒ 整条 handler 中断。

修法：捕获/释放各自 `try` 包裹，抽成 `capturePointer` / `releasePointer`。
并新增**源码门** `tests/client/minimap-gesture.test.ts`，钉住「不得出现裸调用」。

### 3.2 源码门的形式

源码门读源码文本，断言「某类写法不存在」。它不是行为测试，是**结构测试**。

**为什么需要**：某些缺陷是「写法的函数」，不是「数据的函数」。行为测试需要构造
特定输入才能触发，源码门则直接禁止写法。

**边界**：源码门会随代码风格变化而误报。因此它必须**精确到模式**（例如「裸的
`setPointerCapture` 调用」），而不是宽泛地禁止某个函数名。

## 4. 变异自证：证明测试真的会响

### 4.1 方法论

1. 把缺陷**写回源码**（例如把 `capturePointer` 换回裸调用）；
2. 跑测试，断言**恰有 N 条失败**；
3. 把修复写回；
4. 断言全部变绿。

**只有第 2 步成立，第 4 步才算证据。** 如果第 2 步测试不响，说明之前的「通过」是假的。

### 4.2 本项目的真实案例

| 案例 | 变异实验 |
|---|---|
| 小地图手势 | 写回裸调用 ⇒ 恰 1 条断言 FAIL；修复后 0 未捕获异常 |
| 面板凭证 vs 动作路径凭证 | 端到端门断言「面板凭证 == 动作路径凭证」，并经变异实验自证会响 |
| 两处装配收敛 | `Guard.revisionFactsFrom` 是唯一收敛点；端到端门断言 |

### 4.3 一般化

变异测试的三要素：

- **变异子（mutant）**：一个「故意引入缺陷」的自动变换；
- **存活（survival）**：测试没抓住，说明测试不够；
- **死亡（kill）**：测试抓住，说明测试有效。

本项目目前**手工**做变异自证（写回缺陷 → 跑测试），而不是引入 Mutator 工具。
理由：本项目缺陷多是「结构/时序」类，标准变异子不一定能生成；手工变异更贴近真实缺陷。

**改进方向**（见 `07` 的 RQ4）：把高频变异子自动化（删除 `try/catch`、交换比较方向、
移除 `phase` 字段、改指针文件路径）。

## 5. 端到端门：走宿主真实数据流

### 5.1 反漂移双门

v0.12 的展示投影接线，用两道门：

| 门 | 类型 | 内容 |
|---|---|---|
| 契约源码门 | 静态 | 源码里必须有接线 |
| 宿主行为门 | 动态 | 走宿主同一条数据流 `execute → presentationMeta → presentResult`，含旧记录回放的诚实降级 |

**为什么需要双门**：源码门不能证明「运行时真的消费了」；行为门不能证明「所有路径都接线了」。
两者互补。

### 5.2 类型漂移是「写了不消费」的恶果

本项目曾把本地视图类型换成宿主词汇（`ToolCallView` / `ToolResultView`，
`content` 是 `ContentBlock[]` 而非 `string`）。**类型漂移正是「写了不消费」的恶果**：
投影代码写好了，但没人把它接进宿主的数据流，类型对不上也不报错。

## 6. 快照逐字节比对

数学模型的输出用**快照契约**：同样的输入必须得到逐字节相同的输出。

**为什么**：

- 确定性是白盒审计的前提；
- 「同样的数据两次渲染位置相同」是可复现性的最低要求；
- 逐字节比对能抓住「浮点舍入不一致」「Map 插入序变化」这类隐性漂移。

**实现手段**：

- 内部值统一 4 位小数（只为比对）；
- 显示位数按样本量降级（`displayDigits`）；
- 排序带确定性兜底（同刻按包名字典序）；
- 图谱用分层布局而非力导向。

## 7. 真机用户旅程验证

单元测试 + 源码门 + 端到端门都不替代**真机**验证。本项目多次从真机用户旅程发现缺陷：

| 版本 | 真机发现 | 修复 |
|---|---|---|
| v0.12.1 | 强杀后 `bootMarker` 残留而 `crashSeq=0` | 补第二条崩溃信号通道 |
| v0.12.1 | 小地图点击无反应（可选链不防抛异常） | `try` 包裹 + 源码门 |
| v0.11.4 | 双指捏合缩放 | 同一不变式（锚点不动） |
| v0.11.3 | 边完全不可点击 | 透明宽描边热区 |
| v0.11.2 | `reenable` 假成功 | 只有真的 applied 才算成功 |
| v0.11.1 | 宿主自动升级后连续崩溃 | 预发布兼容 + 启动不抛 + 失效锁自愈 |

**真机验证的方法论**：

1. **构造真实崩溃**：强杀进程（SIGKILL）、OOM、断电（不可控，用强杀近似）；
2. **观察产物**：bootMarker、crashSeq、决策文件、journal；
3. **观察下一轮启动**：守护行是否生效、嫌疑插件是否被挡；
4. **回归**：写回缺陷，确认能复现，再确认修复。

## 8. 诚实边界测试：`null` ≠ 0

每个模型的失效条件都必须写成测试：

| 模型 | 失效测试 |
|---|---|
| `intervalSurvival` | 间隔数 < 3 / 含 0 间隔 / 全等间隔 ⇒ `defined:false` |
| `controlBand` | 间隔 < 2 ⇒ 不可判定；全等 ⇒ 带宽 0 是**真值** |
| `markovAnalysis` | 迁移历史为空 ⇒ 不可判定；白名单外迁移被丢弃并计数 |
| `crashRate` | 观测数 0 ⇒ 不可判定 |
| `crashPressure` | 无观测 ⇒ 不可判定；全平稳 ⇒ 0 是真值 |

**为什么这是最重要的一类测试**：失效条件最容易在重构中被「顺手改掉」。
把失效条件写成断言，等于把「模型的诚实性」钉死在测试里。

## 9. 性能基线门（E5）

`performance-baseline.md` 给出可复现口径：

| 项 | 基线 | 警告 / 告警 |
|---|---|---|
| 同步启动开销（`apply()` 内同步 IO 次数） | ≤ 6 | 8 / 12 |
| 守护行安装（10 个第三方插件） | ≤ 60 ms | 120 / 240 |
| 嫌疑排序（50 个插件） | ≤ 3 ms | 10 / 30 |
| 风险排名（50 个插件） | ≤ 2 ms | 8 / 25 |
| 图布局（200 节点 / 300 边） | ≤ 8 ms | 25 / 60 |
| 面板快照构造 | ≤ 25 ms | 60 / 150 |
| 命中测试（200 节点网格） | ≤ 0.05 ms | 0.2 / 1 |

**关键取舍**：守护行安装**必须同步**——这不是为了性能，是为了**正确性**
（异步会输给崩溃）。代价是启动时多几次同步 IO。

## 10. 通过门槛与迭代门禁

### 10.1 单次迭代

```
npm run build      # 零错误
npx tsc --noEmit   # 类型检查
npm run lint       # noUnusedLocals / noUnusedParameters
npm test           # 四层测试
```

**全部零错误才算完成**（`docs/agents/verification.md`）。

### 10.2 收敛门禁 G0–G3

| 门 | 名称 | 要求 |
|---|---|---|
| G0 | 评估基线就绪 | `require_quality: true` |
| G1 | 任务清单清零 | — |
| G2 | 测试报告零错误 | `require_quality: true` |
| G3 | 构建零失败 | `require_quality: true` |

**测试报告必须落盘**：评估器把 `test-reports` 目录不存在判 FAIL。
**别只跑测试不写报告**——这是本项目踩过的坑。

### 10.3 评估维度 E1–E8

E1 意图对齐 / E2 规格符合 / E3 测试覆盖 / E4 代码质量 / E5 性能基线 /
E6 安全检查 / E7 文档同步 / E8 回归完整性。

### 10.4 HITL 门禁 H1–H4

H4 ledger 冲突**保持 BLOCKED**（append-only，人才能改）——
这是「人类在门禁处保留判断权」的具体体现。

## 11. 假绿清单（本项目踩过的）

| 假绿 | 表现 | 根因 | 修复 |
|---|---|---|---|
| 测试追加在 `process.exit` 之后 | 文件打印 ALL PASS，但断言从不执行 | 追加位置错误 | 断言插在汇总行**之前**，且确认 PASS 真的打印 |
| `reenable` 返回 true 但没生效 | 面板显示成功 | 无条件返回 | 只有真的 applied 才算成功 |
| 指标显示正常但系统在崩 | 面板全绿 | 模型被数据拒绝却未标注 | 加 `defined:false` / `shapeAtBound` / `reliable` |
| 测试跑在未装机代际 | CI 全绿但装机崩 | devDep 与装机版本不符 | 契约门用 `runtime/` 装机版本见证 |
| 契约清单漏一条 | 能力图显示「完整」但实际缺 | 单向比对 | 双向比对 + 100% 覆盖目标 |

## 12. 验证体系的扩展方向

1. **自动化变异测试**：把高频变异子做成工具（见 `07` RQ4）。
2. **跨工作区回归**：多分区并行跑同一测试矩阵，验证隔离不串扰。
3. **故障注入**：在沙箱 profile 中主动注入「坏插件」，验证守护行为（而非只测单元）。
4. **性能趋势看板**：把 E5 基线接入 `.cycles/performance-baseline.md` 的自动填充。
5. **文档即测试**：把本套研究文档里的「失效条件表」变成可执行的断言清单。
