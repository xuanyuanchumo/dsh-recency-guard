# 10 · 参考插件研究：取长补短

> 目的：把四个同类/邻近插件的实现技巧沉淀下来，作为 dsh-recency-guard 自举迭代的
> 技术输入。研究方式**只读**，证据给到 `文件:行号`。
>
> 研究对象：`dsh-compat-guardian` v0.2.1、`dsh-ops` v0.5.2、`dsh-context` v0.83.0、`dsh-cookie-guard` v0.1.1。

## 0. 一句话结论

| 插件 | 护城河 | 对 recency-guard 的价值 |
|---|---|---|
| dsh-compat-guardian | 声明式冲突 + 确定性分类 + 贪心求解 + 离线可写救援 | **最高**：补上「崩溃前的确定性检测」 |
| dsh-ops | `when:` 激活门控 + 动态子插件 + remote 契约降级 + presentationMeta 有界事实 | 高：插件组织与展示投影 |
| dsh-context | `deps` 声明式 JSON 路由 + 镜像 fallback + degraded 标志 | 中：面板数据面形态 |
| dsh-cookie-guard | 纯声明式 `cordis.patch.yml` 修复 + 空 apply 占位 | 低但启发：最小可行形态 |

**recency-guard 已优于参考实现的三点**（不要为了「借鉴」而回退）：

1. **capability 投影双向比对**——recency-guard 把「索引是投影不是真相源」写成纪律并配契约测试；
   dsh-ops 是「单一 catalogue 即真相」，没有双向比对。
2. **崩溃信号双通道 + 概率性证据**——哨兵 + bootMarker + pidAlive + 四分类 + `confirmRounds`；
   dsh-ops 无进程级死因概念。
3. **HTTP 路由 vs @Remote 的论证**——`src/routes.ts:4-11` 明确面板无 Agent 身份，走 HTTP 而非 @Remote。

## 1. dsh-compat-guardian（最同类）

### 1.1 声明式冲突元数据 + findings 分类

compat-guardian 读第三方插件的 `dshCompat` 声明（requires / conflicts / services / tools /
capabilities / permissions / platforms / priority），产出 **13 类 finding** 并分 severity
（`warning` vs `error`），其中 `declared-conflict`（声明式互斥命中）是**确定性证据**。

证据：`lib/core.js:26-52`（`dshCompat` 结构）、`:81-139`（13 类 finding）、`:122-125`（declared-conflict）。

**对 recency-guard 的意义**：现在只能靠崩溃反推，compat-guardian 让冲突在**崩溃前**就能确定性判定。
落地方向：读取第三方插件的 `dshCompat`，把 `declared-conflict` / `dsh-version` / `duplicate-service`
作为确定性证据直接进 `assessConfidence` 的 `deterministic` 分支，无需等 `confirmRounds`。

### 1.2 贪心迭代求最小隔离集

`checkCompatibility` 每禁用一个就**重算一遍 error 集合**，直到 error 清零或无候选，
返回 `{ findings, quarantine, unresolved }`（`lib/core.js:142-157`）。
`unresolved` 是「受保护组件导致的无法自动解决的残余 error」，面板据此提示。

**对 recency-guard 的意义**：`pickSuspects`（`src/recency.ts:163`）只切片，**不保证解除冲突**。
升级方向：`recover()` 里循环「取候选 → `disableBundle` → 重算 error」，并保留 `unresolved` 提示。

### 1.3 依赖联动停用（传递性隔离）

隔离一个 bundle 后，依赖它的 bundle 一起进入停用计划（`README:61`、`core.js:148-154`）。

**缺口**：recency-guard 隔离一个 bundle 后，依赖它的 bundle 可能继续崩。

### 1.4 离线 rescue 可写 + 哈希 + 中断恢复

compat-guardian 的 `rescueProfile` 写**两阶段**：先写记录（prepared）→ 原子改 profile →
标记 applied（`core.js:561-603`）。恢复时用 `beforeHash`/`afterHash` + `interruptedAfterWrite`
检测「进程在 ②③ 之间死掉」，并按**原 index 精确回插**（`core.js:607-638`）。

**对 recency-guard 的意义**：`bin/rescue.mjs` 目前**纯只读**（`bin/rescue.mjs:19-20` 注释明说
「写操作留给宿主」）。compat-guardian 让它能在宿主崩溃后真正修复。

### 1.5 跨进程锁 + 原子写

`withFileLock` + `open(tmp,'wx') → sync → rename`（`core.js:176-202`）。

**缺口**：recency-guard 崩溃路径用同步 `writeFileSync`（正确，因为崩溃路径不能 await），
但**常态** `updateState`/`writeDecision` 无锁、非原子。

### 1.6 客户端远程契约挂载 + 降级 + ErrorBoundary

`remote.$mount()` 失败时 `inject([remote.${service}])` 降级，面板根包 `ErrorBoundary`
（`client.js:60`）。

**缺口**：recency-guard 面板走 HTTP，host 不可达即整块失效。

### 1.7 候选排序：未激活优先 + priority 升序

compat-guardian 排序键是「未激活优先 → `dshCompat.priority` 升序 → 列表靠后」
（`core.js:151`），把对用户的影响压到最小。

**缺口**：recency-guard 的候选排序纯按 recency。

## 2. dsh-ops

### 2.1 `when:` 激活门控的工具注册

```js
ctx.tools.register(definition, { when: async (activation) => ... })
```

`when` 返回 true 时该工具对该 activation 可见；配合 `presentation.js:11-36` 的
「探测不发布」（`inspectPresentation` 只读组装结果，不真的发布）。

证据：`lib/publication/registrar.js:161-169`、`native.js:79-80`、`discovery/controller.js:116`。

**缺口**：recency-guard 用 `defineTool`（`src/tool-registration.ts:48-49`），无 per-activation 可见性控制。

### 2.2 动态子插件挂载 + enable 开关

根入口用 `host.plugin({name, apply:(ctx)=>module.apply(ctx,state.config)})` 按 config 的
`enabled` 挂载/卸载 13 个 feature 子插件（`lib/index.js:29-38`、`:48-67`）。
关掉某个 feature 的开关并保存 → 该子插件 fiber 被卸载，副作用精确拆除。

**缺口**：recency-guard 只有 routes 一个子插件（`src/routes-plugin.ts`），
没有「按 Config 开关动态挂载多个 feature 子插件」的组合根模式。

### 2.3 remote `$mount` + stub 抛错降级

客户端 apply 先 `remote.$mount(RUNTIME_REMOTE)`，失败记 `mountError` 不抛；
`lookup()` 用 `ctx.get('remote.<ns>') ?? ctx.get('remote.<pkg>')`；
缺席时返回**会抛错的 stub** 而非伪造错误信封（`lib/client/index.js:15-46`）。

**可借鉴**：recency-guard 的 `client/api.ts` 失败路径可用「stub 抛错让组件自报失败」的形态。

### 2.4 presentationMeta 有界事实提取

`outcomeFacts(value)` 只拷贝 `status` / COUNTERS / FLAGS / `error.code` / `effectState`，
**路径、消息、payload 永不离开 value**（`lib/kernel/presentation-outcome.js:8-33`）。

**可借鉴**：recency-guard 的 `tool-presentation.ts` 若返回了原始路径/消息，可裁剪。

### 2.5 ConfigError rejectUnknownKeys + `~standard` validate

未知配置键**抛错命名 offending key**，而非静默忽略（`lib/config.js:41-47`）。
Config 带 `~standard.validate`（`settings/schema.js:14-28`）。

**缺口**：recency-guard 的 Config 是 interface（`src/index.ts:49`），可能缺未知键 fail-loud。

### 2.6 `dsh-plugin.json` manifest 面

dsh-ops 有额外的 manifest：`facets.host.entry`、`requires.contracts`、`permissions`、
`contributes.x-tool-namespaces`、`contributes.x-components`（`dsh-plugin.json:1-169`）。

**缺口**：recency-guard 目前只有 `dsh.manifestVersion:1`。**上架市场/声明权限/工具命名空间必需**。

## 3. dsh-context

### 3.1 `deps` 声明式 JSON 路由 + 错误信封

`q({ctx, deps:[...], path, label, handler})`，handler 返回 `{ok:true, value}` 或
`U('dsh-context/bad-request', ...)` 错误信封。`deps` 声明该路由依赖的宿主服务。

**可借鉴**：recency-guard 的 `routes.ts` 可对齐「deps 声明 + 结构化信封」。

### 3.2 镜像 fallback + degraded 标志

远程数据依次尝试 `raw.githubusercontent.com` 与 `gh-proxy.org`，失败返回
`{recoms:[...], degraded:true}`，不假装成功。

**可借鉴**：recency-guard 的「数据不可得」应显式 `degraded`，与 `Metric.defined` 纪律一致。

---

## 4. dsh-cookie-guard

纯声明式修复：`cordis.patch.yml` 把 `@deepseek-ai/dsh-client-connection` 的 cookie 生命周期
从 30 天收敛到 7 天，根治 HTTP 431。`lib/index.js` 只是空 apply 占位 + 一条 logger。

**启发**：不是所有问题都需要运行时逻辑——声明式 patch 有时是最小可行形态。

## 6. 学习纪律

1. **只借纪律，不借语法糖**——每个借鉴点都要能落到 recency-guard 的具体代码。
2. **先问「能不能复用已有 machinery」**——`RingBuffer`、`intervalSurvival` 已存在。
3. **不为了「借鉴」而回退已优的实现**——capability 投影、崩溃信号双通道、HTTP 路由论证都不要改。
4. **证据给到 `文件:行号`**——没有证据的「借鉴」是空谈。
