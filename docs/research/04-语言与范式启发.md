# 04 · 语言与范式启发

> 目的：本项目的设计纪律，很多不是从 TypeScript 语法本身来的，而是从其他语言/范式
> **移植过来的习惯**。把这些移植关系写出来，有两个好处：
> 1. 未来换语言/换框架时，纪律能被主动带走，而不是被遗忘；
> 2. 评审时能问「这个纪律是从哪借来的，它在源语言里解决什么问题，移植后是否仍然成立」。
>
> 纪律：**只借纪律，不借语法糖**。每一节都要能落到本项目的具体代码。

## 0. 借纪律的三条原则

1. **借「让错误无法表示」的能力**——类型系统、状态机、所有权，而不是「写得更少」。
2. **借「让隐藏变得可见」的能力**——Result/Option、不可空类型、观测面，而不是「更简洁的代码」。
3. **借「让验证变便宜」的能力**——纯函数、不可变数据、契约测试，而不是「更快的运行」。

---

## 1. TypeScript：类型即契约

### 1.1 `Metric<T>` 用类型表达「不可判定」

```ts
interface Metric<T> {
  value: T | null
  defined: boolean
  // ...
}
```

**启发**：与其约定「无数据时 value 给 0」，不如**在类型层面让「有值但未定义」无法构造**。
`undefinedMetric` / `definedMetric` 两个构造器独占赋值路径，上层不得手写字面量。

**移植自**：Rust 的 `Option<T>` / `Result<T, E>`（见第 3 节）、Haskell 的 `Maybe`。

**验证**：`tests/unit/observability-math.test.ts` 断言 `defined:false ⇒ value===null`。

### 1.2 窄投影接口 `BundleLike`

`recency.ts:14` 只声明 `ctx.pluginManager.listBundles()` 里本插件真正依赖的字段。

**启发**：面向**最小接口**编程（OCP 的负向应用）。宿主返回体再大，也不依赖它的全部形状，
减少宿主升级带来的耦合面。

### 1.3 字面量路由路径

`src/routes.ts` 的路径必须是**字面量**，契约测试核对。

**启发**：路由字符串是**跨层词汇表**。写成常量会被篡改，写成运行时拼接会漂移。
字面量让「路径」成为可被静态核对的契约。

## 2. 函数式编程：纯函数 + 快照契约

### 2.1 数学模型全是纯函数

`markovAnalysis`、`controlBand`、`riskScore`、`crashTrend`、`intervalSurvival`
都是纯函数：**不读盘、不写盘、不取时间（或时间作为参数注入）**。

**启发**：

- 纯函数可以被逐字节比对（快照契约测试的基础）；
- 崩溃路径上，纯函数不会「死一半留下半成品」；
- 时间注入（`now = Date.now()`）让结果**可复现**。

### 2.2 不可变投影

能力图 `upsert` 时**引用拷贝**关系数组；快照「一次成型，多视图共享」。

**启发**：React 的不可变数据纪律（见第 8 节）在宿主层同样适用——
「一份数据、多个视图」要求数据不可变，否则视图之间互相污染。

---

## 3. Rust：所有权、借用与 `Option`/`Result`

### 3.1 `Metric<T>` = `Option<T>` 的工程化

Rust 的 `Option<T>` 强制处理「无值」分支。本项目的 `Metric<T>` 在此基础上加了
`defined` 布尔 + `reason` 文本 + `formula/inputs/confidence` 白盒元信息。

**为什么比 `Option` 更严格**：`Option` 只保证「有没有值」，不保证「值与语义一致」。
本项目的 `defined` 与 `value` 必须一致，且不可判定时必须给**理由**——这是
`Result<T, E>` 的思想（错误必须是值）。

### 3.2 无 NaN 比较

`recency.ts:154 sortableTime` 把不可解析的时间映射为 `Number.NEGATIVE_INFINITY`，
而不是让 `NaN` 进入比较器。

**启发**：Rust 里 `f64::NAN` 的比较是未定义行为（返回 false）；JS 里更隐蔽——
`NaN` 参与比较**恒为 false**，会让排序结果变成**实现定义的顺序**。
把 NaN 在入口处消灭，是对「比较运算的语义」负责。

### 3.3 借用检查器 → 引用拷贝

能力图 `upsert` 拷贝关系数组，而不是持有调用方的引用。

**启发**：Rust 的所有权规则防止「调用方之后改了数组，索引静默变化」。
JS 没有借用检查器，只能用**显式拷贝**来获得同样的保证。

## 4. Go：`fail fast`、`context` 与错误是值

### 4.1 启动绝不抛出

`boot()` 失败改为**降级留痕**（步骤记失败 + 警告日志），不再 rethrow。

**启发**：Go 的哲学是「错误是值，应该被处理而不是被抛」。观测/恢复设施如果抛出，
会把宿主变成 `dsh: fatal load failure`（退出码 1）。**一个可恢复的写锁超时不能拖垮主流程。**

### 4.2 超时与清理

失效锁自愈的判据包含「文件年龄 > 5s」；启动恢复延后 1.5s 且定时器 `unref()`。

**启发**：Go 的 `context.WithTimeout` 让超时成为一等公民。本项目把「超时后的清理」
做成显式步骤（`cleanStaleLocks`），而不是依赖「等一下就会好」。

### 4.3 `panic/recover` 的边界

Go 用 `panic` 处理「不可恢复」，用 `recover` 兜底。本项目的对应物是：
守护行表达式用 `try { ... } catch { return false }` 兜底——**守卫表达式永远不抛**。

## 5. Lisp / Scheme：`eval` 的声明式守卫

### 5.1 守护行表达式是一个求值式

`decision.ts:139 guardExpression` 生成的是一段**自包含的求值式**：

```js
(() => { try { ...read pointer... ...read decision... ...return includes(...) } catch { return false } })()
```

**启发**：Lisp 的核心是「代码即数据，求值即语义」。这里把「拦截决策」写成
一个**声明式表达式**，由 Loader 在 `with (ctx) { eval(expr) }` 里求值，
而不是由插件在运行时主动拦截。

**为什么安全**：

- 作用域里**没有 `require`**，只能读 `fs`（`process.getBuiltinModule('fs')`）与 `profileContext`；
- 整个式子被 `try/catch` 包裹，任何异常都返回 `false`（放行）；
- 包名做了转义（`\` 与 `'`）。

**边界**：`eval` 是危险原语。这里能安全使用，是因为**输入源是插件自己生成的表达式，
且失败语义是 fail-open**。换一种失败语义（fail-closed）就绝不能用 `eval`。

## 6. Prolog / 声明式：状态机白名单表

### 6.1 迁移表

`lifecycle.ts:80 ALLOWED` 是一张显式白名单：

```ts
const ALLOWED: Record<GuardStage, readonly GuardStage[]> = {
  idle: ['monitoring'],
  monitoring: ['crashed', 'idle'],
  crashed: ['deciding'],
  deciding: ['stabilizing', 'monitoring', 'crashed'],
  stabilizing: ['recovered', 'monitoring', 'crashed'],
  recovered: ['monitoring', 'idle'],
}
```

**启发**：Prolog 的「事实 + 规则」风格。状态机的合法迁移是**事实**，不是
散落在各处的 `if`。用白名单而非黑名单的理由：**新增状态时若忘了补迁移表，
编译/测试会暴露它，而不是让它悄悄变成可达的死角**。

### 6.2 YAML 声明式配置

`cordis.patch.yml` 是声明式补丁（insert / override by id / group / disabled / `!!js`）。

**启发**：配置的形态应让「意图」可读、可 diff、可校验。这也是为什么
守护行发射**永远加引号**——`@` 是 YAML 保留指示符，scoped 包名会让整份 profile patch
不可解析。

---

## 7. SQL / 关系代数：快照一次成型，多视图共享

### 7.1 面板快照

`snapshot.ts` 把一次快照做成**一份不可变投影**，面板 KPI 条、卡片、图谱、事件流
全部读同一份。

**启发**：SQL 视图是「同一份表的不同投影」，不是「再查一次」。
如果两个视图各拉一次，会出现**界面自相矛盾**（而且省不掉往返——本项目反而因此
省了一次请求）。

### 7.2 白盒契约 `formula/inputs`

每个派生量带定义式与输入摘要。

**启发**：关系代数要求每个派生表可追溯到基表。`formula` 是「派生规则」，
`inputs` 是「基表快照」，`sampleSize`/`confidence` 是「数据质量」。

---

## 8. React：不可变投影与组件拆分

### 8.1 纯函数视图模型

`graph-model.ts`、`panel-model.ts`、`viewport.ts`、`minimap-model.ts` 全是**纯函数**，
React 组件只是它们的薄壳。

**启发**：

- 纯函数视图模型可以被**无浏览器测试**驱动（`tests/client/*.test.ts` 用 tsx 直接跑）；
- 组件拆分遵循「一个职责一个文件」，与 `src/` 的拆分纪律一致。

### 8.2 单一真相

图谱的选中态与节点详情**互斥**（单一真相），Esc / 空白点击 / 「重置」都会清空。

**启发**：React 的单向数据流。多个 UI 状态若各自为政，会出现「点了节点但详情是上一个」。

## 9. 语义化版本（semver）与预发布区间

### 9.1 兼容闸门

`package.json` 的 peer 范围与 `engines.dsh` 都用**显式预发布分支**：

```
>=0.2.1-rc.5 <0.2.2-0 || >=0.2.2-rc.1 <0.2.3-0 || >=0.2.3-rc.1 <0.3.0-0
```

**为什么**：node-semver 只放行「与范围中某个比较符 major.minor.patch 元组相同且自身带
预发布标签」的预发布版本。旧范围 `>=0.2.1-rc.5 <0.3.0-0` 会**静默排除 `0.2.2-rc.1`**，
插件被兼容闸门判为不兼容并从 profile 移除。

**启发**：semver 的预发布语义是**约定**，不是语法。必须显式列出每个发布线。

### 9.2 依赖代际对齐

devDependencies 与装机版本对齐到 `0.2.2-rc.1`。

**启发**：**测试跑在一个从未有人装过机器的代际上，绿灯不代表装机绿。**
契约测试用 `runtime/`（从 app.asar 解出）的装机版本做 `semver.satisfies` 判定。

## 10. ESM：严格模块与 `type: module`

`package.json` 用 `"type": "module"`，所有内部导入带 `.js` 后缀。

**启发**：ESM 的严格性（无 `require`、显式导出、无文件扩展名猜测）让「模块边界」
可静态核对。这对本项目很重要：守护行表达式里**没有 `require`**，
正是 ESM 严格性的自然结果。

---

## 11. `Map` / `Set` 语义与插入序

能力索引用 `Map` 保证插入序，消费者/生产者用 Set 语义（去重）。

**启发**：JS 的 `Map` 保持插入序、`Set` 去重——这两个语义被**刻意使用**，
而不是随意用数组。索引的输出稳定性依赖它们。

---

## 12. 零依赖 CLI：`bin/rescue.mjs`

宿主起不来时，`node bin/rescue.mjs status|history|decision|archives` 离线读取守护产物。

**启发**：**零依赖、只读、语义化退出码**（2 = 有未恢复崩溃，供脚本联动）。
这是「逃生通道」的具体形态——它不依赖宿主、不依赖插件框架、不依赖任何第三方包。

**为什么零依赖**：逃生通道本身崩溃的概率必须**低于**宿主崩溃的概率。

## 13. 中文语言本身：压缩的知识与术语纪律

本篇标题里的「中文思维」不只是哲学，也包含**中文语言本身**的工程价值：

| 语言特征 | 工程价值 | 本项目用法 |
|---|---|---|
| 单字表意 | 术语压缩，沟通成本低 | `嫌疑`、`守护行`、`指针文件`、`分区键` |
| 成语 = 压缩的因果 | 一句顶一段推理 | `防微杜渐`、`过犹不及`、`有备无患`、`适可而止` |
| 对仗/排比 | 规则成组，易于审查 | `宁可过放行，不可过拦截` |
| 一词多义需辨析 | 强制精确定义 | 本项目区分 `consumes` / `consumedBy` 方向 |

**纪律**：术语一旦进入代码注释，就必须**全仓一致**。中文注释必须说明「为什么这样写」，
不复述代码在做什么——否则注释只是噪声。

## 14. 移植性检查清单

从别的语言/范式借纪律时，逐项问：

| 检查 | 说明 |
|---|---|
| 源语言为什么需要它 | 它解决的是源语言的什么缺陷？ |
| 目标语言是否有等价机制 | JS 没有借用检查器，只能用显式拷贝替代 |
| 移植后是否仍然成立 | `eval` 守卫在 fail-open 下安全，换 fail-closed 就不安全 |
| 是否有测试钉住 | 没有测试的纪律会在下一次重构中消失 |
| 是否写进 CLAUDE.md | 反复犯的错应沉淀为约定，而不是只留在注释里 |

下一篇 `05-验证与可证伪体系.md` 讲如何用测试与变异实验把这些纪律钉死。
