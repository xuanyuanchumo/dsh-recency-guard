## 0. 为什么需要这份报告

「杀灭率 47.5%」本身**不是一个结论**。同一个数字背后可能是三种完全不同的东西：

1. **测试真的不够**（真实缺口）→ 该补测试；
2. **变异体是等价的**（改了代码但行为不变）→ 该修**工具**，不是修测试；
3. **不可判定**（缺样本、平台差异）→ 该登记，不该假装有结论。

把三者混在一起报一个数字，就是用「看起来严谨的指标」掩盖「没做归因」——
这正是研究文档 05 §4 批评的「看起来绿」。所以每个存活体都必须归到某一类，
且归因理由要能被别人复核（给出代码行 + 为什么等价/缺口）。

## 1.1 cycle-13 复核修正：B 类里有 3 条**不是**等价体

初版把 §3 里 12 个 comparison 类存活体整体归为「等价」。cycle-13 逐条复核后，
**有 3 条被推翻**，改为「真实测试缺口」并已补测试杀死：

| 位置 | 初版判断 | 复核结论 | 处置 |
|---|---|---|---|
| `control-band.ts:40` | 等价（以为 `gap > 0` 无差别） | **错**。重复时间戳会产生 `gap = 0`，`>= 0` 会把它纳入样本，把 x̄ 与 MR̄ 一起拉偏 | 已补断言（x̄ 必须 = 2000 而非 1500）⇒ **KILL** |
| `lifecycle.ts:256` | 等价（以为没有夹具） | **错**。`i > 0` 会永远关不掉 index 0 的区间 ⇒ 单区间时 `openSteps` 永不为空 | 新增 `tests/unit/lifecycle-steps.test.ts` ⇒ **KILL** |
| `risk-bayes.ts:146` | 初版已标「存疑」 | 存疑 = 未证，**不能算等价** | 留在分母里，如实计为缺口 |

**这条修正的意义**：等价判定不能靠「读起来像是没影响」，必须能指出
**哪个输入下行为不同**（或证明那个输入不可达）。初版 3 条里 2 条是
「凭直觉判等价」——这正是变异测试要防的思维习惯，却发生在我写归因报告时。

### 2.1 这轮 A 类还暴露了我自己的一个测试缺陷

第一次写 `display-truncation.test.ts` 时，我用 `/省略/` 去匹配提示文案，
但 `omittedNote` 的真实输出是 ``… 其余 N 项未展开（…）`` —— **函数里根本没有「省略」二字**。
结果：变异体依然存活，而我的新测试全绿。这是「测试在测一个不存在的字符串」，
比没有测试更危险（它给出虚假的安全感）。

教训（已可复用）：**断言的锚点必须与实现文案同源**。写文案断言的正确姿势是
从被测模块的常量/函数注释里取原文，而不是凭印象猜一个近义词。

## 3. B 类 · 等价变异体（共 14 个，应修工具而非补测试）

等价的判据：**改了这处，任何输入下程序行为都不变**。下列每一类都给了可复核的理由。

### 3.1 循环边界 `i < len` → `i <= len`（5 个）

| 位置 | 变异 | 为什么等价 |
|---|---|---|
| `control-band.ts:38` | `i < crashTimes.length` → `<=` | 多出的一轮访问 `crashTimes[len]`，取到 `undefined`，被 `?? 0` 兜底成 0；随后 `gap = 0 - last`，若为负则被 `gap > 0` 过滤。**除非最后一个间隔恰好为负且被加入**——不可能，因为 `gap > 0` 是守卫。 |
| `markov.ts:166` | `i < a.length` → `<=` | 越界取到 `undefined` → `?? 0`，`Math.abs(0 - b[i])` 若 `b[i]` 也越界则为 `|0-0| = 0`，不改变 `max`（`max` 初值 0）。 |
| `risk-calibration.ts:266` | `i < events.length` → `<=` | 越界 `event` 为 `undefined`，`if (!event) continue` 直接跳过。**这行守卫让边界变异等价**。 |
| `risk-calibration.ts:293` | 同上 | 同上（第二个循环有同一守卫）。 |
| `patch.ts:76 / :90` | `i < scanned` → `<=` | 已在补 `.js` 导入后**被杀死**（非等价），行数统计里已不计入存活。 |

### 3.2 阈值比较 `x < 1` ↔ `x <= 1`（4 个）

| 位置 | 变异 | 为什么等价 |
|---|---|---|
| `observability.ts:120` | `sampleSize < 1` → `<= 1` | `sampleSize === 1` 时两个分支都返回 `1`（`if` 返回 1，`else` 走 `log10(1)+0.5 = 0.5` → `round(0.5) = 1` → `max(1, ...) = 1`）。**结果恒等**。 |
| `store.ts:212` | `pid <= 0` → `< 0` | `pid === 0` 时：`< 0` 版本不会把它判为 incomplete，但 `Number.isInteger(0)` 为真且 `processAlive(0)` 为 false（`pidAlive(0) === false`，已有断言）⇒ 仍不进 `report.kept`。**分支终点相同**。 |
| `risk-bayes.ts:146` | `x <= 0` → `< 0` | `x === 0` 时：`< 0` 版本不返回 NaN，继续走 `x < 1` 分支 ⇒ `lgamma(1) - log(0)` = `0 - (-Infinity)` = `+Infinity`，而调用方对 `!Number.isFinite` 有兜底。**净效果都是「不可用」**，但路径不同 ⇒ **这条我标为「等价性存疑」，宁可算它回来**。 |
| `risk-bayes.ts:147` | `x < 1` → `<= 1` | `x === 1` 时：`<=` 版本递归 `lgamma(2) - log(1)` = `0 - 0` = `0`，而 `x=1` 的真值 `lgamma(1) = 0`。**恰好相等** ⇒ 等价。 |

> 诚实标注：`risk-bayes.ts:146` 我无法纯靠推理判定等价（取决于调用方兜底），
> 因此**不把它算作已归类的等价体**，而是标「存疑」。存疑就说是存疑，不硬塞进一个漂亮的分类里。

### 3.3 反向循环边界 `i >= 0` → `i > 0`（1 个）

| 位置 | 变异 | 为什么等价 |
|---|---|---|
| `lifecycle.ts:256` | `i >= 0` → `i > 0` | 只影响**第 0 个** span。该循环从后往前找「最近的同名未结束区间」；跳过 index 0 意味着当且仅当只有第 0 个匹配时才漏关。现有测试未构造该形状 ⇒ **这条其实是「测试覆盖不到的等价假设」，我把它归 B 类但标注「需补一条夹具才能证实」**。 |

### 3.4 「零值守卫」`> 0` → `>= 0`（3 个）

| 位置 | 变异 | 为什么等价 |

| `survival.ts:116` | `zeros > 0` → `>= 0` | **实测确认为等价（不是缺口）**。`crashSeries` 先 `.filter(Number.isFinite)` 再 **`.sort()`**，所以 `gaps` 恒 ≥ 0 ⇒ 「非有限间隔」与「负间隔」两个分支**不可达**；`zeros > 0` 改成 `>= 0` 只是替换了不可达分支的文案。已补一条断言钉住「乱序输入被排序 ⇒ 不产生负间隔」，把这个不可达性**记录为事实**，而不是编一个假用例冒充覆盖。 |

而当前测试从不制造异常。这是 07 §5.2 E4.2 明确的独立里程碑（「注入坏插件/故障注入」），
本轮（M1–M4）不含它。**登记为下一循环任务，不伪装成本轮已完成。**

## 6. 本报告的自我边界

1. **杀灭率 47.5% 不等于「测试强度 47.5%」**。分母是「工具生成的变异体」，
   而工具只覆盖四类文本变换；结构/时序类缺陷（本项目缺陷的主流）不在分母里。
2. **B 类里有 1 条（`risk-bayes.ts:146`）我判不了**，标为存疑而非硬分类。
3. **C 类 9 个不是「不重要」**，是「当前工具链判定不了」。它们指向一个明确的
   下一里程碑（IO 故障注入），而不是一句「以后再说」。
4. 这份报告**不能**替代真机用户旅程 —— 它证明的是「断言会在代码被改坏时响」，
   不证明「产品在真机上是对的」。
