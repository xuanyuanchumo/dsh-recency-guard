# 四插件「取长补短」研究报告（cycle-6 / T1 证据）

> 研究对象：desktop profile 已安装的 dsh-ops@0.5.0、dsh-compat-guardian@0.2.1、
> dsh-context@0.82.1、dsh-cookie-guard@0.1.1（均为发布产物）。
> 研究方法：源码逐文件阅读 + 与本项目逐条对照。研究由研究子代理完成，Lead 审定。

## 一、dsh-ops v0.5.0 —— 工具工程与输出格式标杆

1. **能力目录册（投影即真相源）** `lib/capabilities/registry.js:1-55`：全部工具用一份
   冻结目录册描述（rawName/component/availability/mutates/concurrencySafe/parameters/
   description/output），注册顺序用显式数组固定，派生清单全部由目录册 filter/map 得出。
   与本项目「capability-specs 是投影不是第二真相源」约定同源。
2. **工具文本输出三要素：显示数/完整度/下一步**：
   - `lib/projections/native/render.js:43-60` notices()：输出尾部固定
     `[Notice: N items displayed; complete=…; TruncatedBy: …; nextOffset=…; omitted=…; total=…]`；
   - capNativeText()：按编码字节数二分截断（64KB 预算），尾部附恢复指令，截断点
     回退半个 UTF-16 代理对；
   - result-render.js:24-37：`displayComplete` 与 `pageComplete` 显式分离，
     非完整时输出可执行的 `Next:` 恢复句。
   - 这是本项目「报 N 只列 5」踩坑的成熟解法（本项目已有 omitted 计数，
     原因码与 Next 句是可选增强）。
3. **单行多 feature 宿主架构** `lib/index.js:15-71`：bundle 只插一行；apply() 用
   mount() 逐个挂子插件，可选宿主服务缺失时该 feature pending 而不阻塞工具。
4. **manifest 工程化**：permissions 每条带 scope+reason；x-tool-namespaces 声明
   工具前缀与清单；exports 子路径覆盖 locale/icon。

## 二、dsh-compat-guardian v0.2.1 —— 守护/状态机/自愈标杆（最同构）

1. **工具注册与审批门** `lib/index.js:722-741`：单工具 + action enum 收敛动作面；
   破坏性动作先 approve() 走沙箱审批，只读动作不审批。
2. **状态自愈式 reconcile** `lib/index.js:506-594`：每次 reconcile 先用观察到的实际
   bundle 状态重导出历史记录（不盲信上次落盘），中断后自动收敛；失败计数按
   `name@version|runtimeVersion` 复合键。
3. **持久化健壮性**：原子写 tmp(wx)+fsync+rename、withFileLock 文件锁、
   revision()=sha256 乐观锁写前校验、状态文件带 schemaVersion（非法即报错不静默重建）。
4. **监控循环纪律** `lib/index.js:701-721`：intervalMs 下限 5000 校验；monitor 单飞；
   .catch 只 warn；定时器 .unref()；dispose 置位并等待在途操作。
5. **RPC 与前端**：zod discriminatedUnion 校验 + payload ≤64KB + 单操作互斥；
   客户端 `.dsh-kit` CSS 只用 `--dsw-alias-*` + color-mix；ErrorBoundary + 重试按钮；
   条件续轮询 hook（数据在变 1.5s 自续、稳定即停）。

## 三、dsh-context v0.82.1 —— 可视化与资源自适应标杆

1. **投影 wire 协议**：`{key, stateSchema, init, apply, wire:{viewSchema, view, summary},
   stateVersion}`；客户端拿 viewSchema 校验后的视图；schema 演进用 stateVersion 数字化。
2. **资源自适应与预算节流**：工作预算 8s 主动暂停 2s、每步至少歇 25ms、
   AbortController 贯穿、堆压力 >2/3 让路 —— 与本项目「不做高频轮询」约定互补。
3. **路由纪律**：先 `typeof fetch.register==='function'` 探测再注册，Response 一律
   `cache-control: no-store`（本项目 routes.ts 同款）。

## 四、dsh-cookie-guard v0.1.1 —— 声明式修复与独立救援工具

- 修复本体是 cordis.patch.yml 声明式覆盖；apply 空操作只打一行 info（极简=零崩溃面）。
- `tools/prune-cookies.mjs`：独立 CLI 救援（不装插件可用）——--dry-run 先统计、
  删除前时间戳备份、明确 exit code。（本项目 bin/rescue.mjs 同形态，v0.9 已有。）
