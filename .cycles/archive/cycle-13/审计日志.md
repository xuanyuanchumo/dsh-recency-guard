## 决策记录（为什么这样做）

| 决策 | 理由 |
|---|---|
| 架构第一层按**运行时**（host/client）而非直接按功能域 | dsh 规范里 `client`/`host` 是不同 group，因为二者是不同运行时（浏览器无 `node:*`）。先切运行时，才能把「client 不得依赖 host」变成结构事实 |
| 边界必须写成测试 | 只挪目录不改边界 = 白改：挪完 client 仍 import host（11 处）。目录是给人看的，边界是给机器守的 |
| 抽 `shared/` 而不是让 client 各写一份 | 两份 `LAYOUT` 必然漂移，且小地图点击会整体偏移而**不报错**（无异常、无测试红） |
| E4.1 未达标不登记无理由等价体 | 为凑 80% 登记「看起来等价」的条目，等于把治理变成自我豁免。门禁 FAIL 是真实结论 |
| 拆环用「最小必要集」而非整批下沉 | 第一次整批搬 17 个符号失败（私有辅助被卷走 + 类型/值混导出）。最小集 10 个符号一次成功，改动面也可控 |
| 自己写导入图测试而不是信评审器 | 评审器按 basename 前缀匹配把 `patch → patch-yaml` 误判成环。图算法 + 反向自检是可复核的判据 |
| Q5 不改成 PASS | R07 不条件通过。正确做法是留下反证（误报 + 不适用），而不是把判据调松 |
| 第一次拆环失败后回滚而不是硬修 | 绿树优先：把 19 个测试文件红着的半成品留在仓库，比保留两个已记录的环危险得多 |
