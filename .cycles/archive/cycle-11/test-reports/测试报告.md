## 4. 变异自证（证明测试真的会响）

只有「能 FAIL 的测试」才算测试。本循环做了两轮：

### 4.1 `decision-compat` —— 让守护行偷读 `evidence`

**变异**：把 `guardExpression` 的 return 改为
`... && (decision.suspects[0].evidence.risk > 0.5)`（一个看起来合理的「风险阈值拦截」）。

**结果**：**恰 4 条断言 FAIL**
- `表达式不读 suspects`（结构门）
- `表达式不读 evidence`（结构门）
- `无 evidence 时拦截命中`（行为门）
- `两种决策文件结果一致`（行为门）

**恢复后**：全部 PASS。

**这条变异证明什么**：如果将来有人把展示字段接进拦截判定，旧版决策文件
（无 `evidence`）会静默全放行 ⇒ 崩溃重演。门会当场抓住。

### 4.2 `install-resilience` —— 恢复静态 import

**变异**：把 `loadDefineTool()` 换回 `import { defineTool } from '@deepseek-ai/dsh-tools'`
并实际使用（正是「看起来更简洁」的重构）。

**结果**：**恰 2 条断言 FAIL**
- `没有 optional peer 被静态 import`（点名 `@deepseek-ai/dsh-tools`）
- `静态 import 的外部包都在 dependencies 里`

**恢复后**：全部 PASS。

**备注**：第一次变异（只加 import 不实际使用）**没被抓住** —— esbuild 把未使用的
import 摇树掉了。这说明变异必须**真实使用**变异点，否则测的是摇树结果而不是写法。
