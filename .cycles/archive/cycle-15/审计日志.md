## 3. 期间发现并修复的 4 个真实缺陷

### D1 路径逃逸（产品缺陷，evidence 修）
- **现象**：verify 新补的直接测试崩在 `ENOENT observation-@scope\pkg.json`。
- **根因**：`cooccurrence-store.ts` 的 `sanitizeName` 白名单含 `/`，且 `.` 未被限制 ⇒ `..` 也能过。
- **实测**：`'@a/../../escape'` → 跳出分区目录。
- **判定**：不是测试错，是**产品缺陷**（安全类：路径逃逸）。
- **修法**：`core/path-safe.ts` **单实现**（两份合并，漂移在结构上不可能）+ `..` 折叠 + `/`→`_` + **改写时加 8 位 sha256**（因为 `'@scope/pkg'` 与真实存在的 `'@scope_pkg'` 会撞名 ⇒ 两个包静默互相覆盖）+ `legacyUnsafeName` 只读回退。
- **未爆发的理由（诚实）**：当前唯一生产调用传常量 `'official-experimental'`，不含斜杠。**潜在漏洞，不是已发生事故**。

### D2 契约测试假环（测试基础设施缺陷，verify 修）
- **现象**：`import-graph` 报值依赖环 `store.ts → journal-io.ts → store.ts`。
- **根因**：语句正则 `[\s\S]*?` **跨行**，从第一条 import 一路吃到第一条相对 import ⇒ clause 混入 `import { existsSync }` ⇒ `import type` 判成值边。
- **为什么现在才爆**：`journal-io.ts` 是第一个「A `import type` B，B 值 import A」的形态。**潜伏已久**。
- **修法**：`(?!\bimport\b)` 否定前瞻 + 2 条合成回归（多语句+末条 type / 相邻两条相对 import 不串味）。

### D3 markov 断言的期望值算错（新测试写错，verify 修）
- 断言期望 4，实际 5（`[1,5]` vs `[1]` ⇒ `|5-0|=5`）。
- 更重要的是 verify 主动更正：**这条断言杀不死 `i<=a.length` 变异体**（越界项 `undefined` 被 `?? 0` 兜底成 0，max 不变）。「导出 + 有断言」≠「已杀死」。

### D4 预警卡裁切 + 轮询间隔不可见（真机缺陷，panel 修）
- **裁切**：`rg-card` 固定高度 ⇒ CUSUM 说明末行被切（与 v0.16「数据流第 4 步被裁」同族）。修法：`height:auto + max-height:360px + overflow-y:auto`（**显式滚动，不静默裁切**）+ 6 条结构断言。
- **轮询间隔不可见**：文案确实渲染但在整个面板最底部（16 卡 + 图谱 + 归档之后）⇒ 用户与验收者都看不到。修法：顶部操作区加 `rg-poll-chip` 徽标（同源文案 + title 说明 3–30s 区间）。
- **判定**：两条都只有真机截图能发现（单测 + tsc 全绿时仍然存在）。这是连续第二轮验证「真机验收不可替代」。

## 7. 教训（进 CLAUDE.md）

1. **假环也是真缺陷**：判据（这里是 import-graph 的正则）自己出错时，它会**稳定地**给出错误结论。修判据要用合成回归钉住，而不是调宽容忍。
2. **白名单里的路径分隔符 = 逃逸洞**：`[^A-Za-z0-9._@/-]` 看似「允许合法字符」，实则允许 `/` 与 `..`。路径安全要用「黑名单剔除 + 不含分隔符断言」双向守。
3. **折叠会造撞名**：`/`→`_` 让 `@scope/pkg` 与 `@scope_pkg` 同投影 ⇒ 必须补指纹，否则「修了逃逸，引入静默覆盖」。
4. **代理指标要先想清方向**：加载耗时用「启动间隔」，但间隔变大 = 更安全 ⇒ 必须取倒数，否则预警方向反掉。**先判方向，再选单位**。
5. **`MetricsSnapshot` 不是万物容器**：「读数」与「预警」语义不同，混装会扩大契约变更面。闭环判据是「有人消费」，不是「塞进同一张卡」。
6. **`import-graph` 这类结构测试要区分「当前行为」与「正确行为」**：把当前行为抄进断言，会把缺陷固化成契约（verify 在 `cooccurrence-store` 上差点这样，及时改成「扁平 + 不越界」不变式）。
