# 技术债 TD-7：`pathSafeName` 的 32 位指纹碰撞（静默覆盖的残余风险）

| 字段 | 值 |
|---|---|
| 登记时间 | 2026-11-11 |
| 登记循环 | cycle-15（T15，sanitize 路径逃逸修复的副作用） |
| 严重度 | P3（概率极低、性质严重：静默覆盖） |
| 归属 | `src/host/core/path-safe.ts` 的 `pathSafeName()` |
| 状态 | 保留（有意接受） |

## 背景：为什么会有指纹

修复「白名单含 `/` ⇒ 路径逃逸」时，把 `/` 折成 `_` 会引入**新的**碰撞：
`'@scope/pkg'` 与真实存在的 `'@scope_pkg'` 会投影到**同一个文件**
（观测快照/备份静默互相覆盖）。因此只对「被改写的名称」追加
原始名的 8 位 sha256 指纹（32 bit）：

```
'@scope_pkg'      -> observation-@scope_pkg.json          （未改写，无指纹）
'@scope/pkg'      -> observation-@scope_pkg-5b9874c8.json
```

## 残余风险

两个**不同的**原始名称若都被改写、且 8 位指纹相撞，仍会落到同一文件。
概率约 2⁻³² ≈ 2.3×10⁻¹⁰（生日界下，实际观测/备份条目数是几十量级，
量级上可忽略）。但后果是**静默覆盖**：两个包的观测快照/配置备份互相踩掉，
而系统没有任何告警。

## 为什么现在接受

1. 触发前提很窄：两个名称都要含非法字符（`/`、空格等），且指纹撞；
2. 影响面是**旁路数据**（观测快照、配置备份），不参与关闭决策；
3. 升级到 64 位指纹只需改一行（`.slice(0, 8)` → `.slice(0, 16)`），
   但会让**已写入的文件名再次变化**（存量可读性再断一次）—— 因此不在
   v0.17.0 这个小版本里做，等下一次破坏性变更（或做成「双读单写」迁移）。

## 触发条件与验证方式

- 若将来出现「两个不同 bundle 的观测/备份内容互相串」，先查这里：
  `pathSafeName(a)` 与 `pathSafeName(b)` 是否相同；
- 单测 `tests/unit/path-sanitize.test.ts` 已覆盖「改写后与未改写 lookalike
  不同名」（`rewritten name differs from an already-flat lookalike`）、
  4 对冲突检查与越界检查。

## 根治方向（下一轮候选）

1. 指纹升到 16 位（64 bit），并做**读取双路径**：先试新名，再试旧 8 位；
2. 或者写入时检测「目标已存在且 bundle 字段不同」⇒ journal note 冲突告警
   （把静默覆盖变成可见冲突，比消除概率更符合本项目「不静默」的纪律）。
