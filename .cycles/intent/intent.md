# 意图（intent）—— dsh-recency-guard v0.2

> 本文件是 AI-Native Iteration Cycle 的**意图基线**。
> E1「意图对齐」门禁以本文件为准。

## 1. 背景与问题

dsh-recency-guard v0.1 解决了一个具体的用户痛点：**添加或更新第三方/实验性插件
导致 DSH 崩溃，必须禁用所有插件再逐个加回**。v0.1 已实现并验证了核心机制：

- 崩溃检测用**进程级哨兵**（Harness 在正常退出与崩溃时都会释放 fiber，插件的
  disposer 无法区分二者；能区分的是退出码）；
- 恢复决策在**崩溃退出那一刻**同步落盘（Loader 并发创建各行，若等到下次启动
  才写决策，会与嫌疑插件那一行的求值竞态）；
- 拦截靠 patch 行的 `disabled: !!js` 表达式（Loader 在导入该行模块**之前**求值）。

v0.1 的验证结论（沙箱 profile `sb-rg`，两个会抛未捕获异常的假插件）：

| 启动 | 结果 | 决策 |
|---|---|---|
| 第 1 次 | 崩溃 | 关闭最近更新的 1 个 |
| 第 2 次 | 崩溃 | 关闭最近更新的 2 个 |
| 第 3 次 | **正常启动** | 稳定 |

## 2. v0.2 的用户诉求（原文拆解）

> 「继续研究以 dsh-anic 的 L4 全自主模式结合 dsh-plugin-dev-kb 插件驱动
> dsh-recency-guard 技能插件进行自举循环迭代升级。确保技能插件的所有的功能业务的
> 注册、生产与消费，同时还要关注技能插件的生命周期步骤流程、状态、可视化和能力
> 业务的实用性连通性完整性逻辑性，要量化、白盒透明化、可视化流动等可观测性
> （充分研究利用各种数学模型和数据结构与算法），添加整理优化完善管理面板，要从软件
> 质量保障/质量属性与全生命周期评审体系（功能性需求 + 非功能性需求 + 设计约束 +
> UX/UI 标准 + 工程化规范，功能与业务、架构与设计、代码与工程、前端与体验、测试
> 体系、非功能与运维、评审与验收、中文注释、响应式布局、合理的数据结构与算法、
> 模块化生产级架构）进行分析，充分利用 dsh 宿主的各种能力，对缺口进行完善补充
> （要有归档插件的产物重新开始执行并能以最新的项目事实执行自举和举他等功能，避免
> 过度的产物影响判断），热更新重载插件，不同项目使用本插件要隔离显示不能污染，
> 优化当前前端包括图谱可视化显示的排版和逻辑（继续优化美观界面现代化，要可交互
> 的图谱，功能还很贫乏，进行研究优化，清理技术债务）。」

拆成 9 条可验收的需求：

| # | 需求 | 验收标准（可观察） |
|---|---|---|
| R1 | 能力业务的**注册/生产/消费**闭环 | 能力清单与实际注册面**双向**比对无差异；三类缺口（消费断链/过度生产/孤立）可被检出并在面板列出 |
| R2 | 生命周期步骤流程与状态 | 状态机有穷举阶段与**白名单迁移表**；非法迁移被拒且不改变状态；迁移历史可查 |
| R3 | 可量化 | 崩溃率、平均恢复耗时、检出率、隔离纯度、稳定性评分、风险分、崩溃趋势**全部有数值**，且**不可判定时为 null 而非 0** |
| R4 | 白盒透明化 | 每个读数带可读文字（颜色不是唯一通道）；决策、迁移、缺口都带**原因与时刻** |
| R5 | 可视化流动 | 面板有**可交互图谱**：滚轮缩放（指针为锚）、拖拽平移、点击高亮、Esc 一次退出 |
| R6 | 管理面板 | 响应式（窄屏单列）、主题变量驱动、只用 `--dsw-alias-*` |
| R7 | 全生命周期质量评审体系 | 分层测试（Core/Host/Client/Contract）+ 契约层双向比对；非功能项（类型、lint、构建）纳入 ANIC 门禁 |
| R8 | 归档重置 + 举他 | 产物归档（留证据链）+ 按**最新事实**重跑；归档不继承旧结论 |
| R9 | 多项目隔离 | 不同项目目录各有一份独立记账；A 的崩溃不影响 B |

另有两项工程约束：**热更新重载**（不能因重载丢状态）、**清理技术债务**。

## 3. 范围外

- 不实现通用插件市场、不实现跨 profile 的共享状态。
- 不替换 DSH 自身的图谱/插件管理 UI（本插件只提供自己的面板与图谱）。
- 不引入新的运行时依赖（除已声明的 `dsh-atomic-write`）。

## 4. 验收基线（意图对齐的判据）

一次验证必须能同时给出：

1. **分层测试全绿**：`npm test` 报告 Core / Host / Client / Contract 四层均 PASS；
2. **类型与构建干净**：`npx tsc --noEmit` 与 `npm run build` 均无错；
3. **沙箱真机链路**：崩溃 → 预启动拦截 → 正常启动，全过程可复现；
4. **隔离可证**：两个项目目录并行使用，A 的崩溃状态不出现在 B；
5. **契约无差异**：能力清单 ↔ 注册面双向比对 `ok === true`。
