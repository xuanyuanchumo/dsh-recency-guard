# 审计日志 —— cycle-17（v0.19.0）

> 时间：2026-11-13（北京时间）。本日志记录**决策与证据**，不记录流水账。

## 1. 本轮的核心发现（按「值不值得记」排序）

### 1.1 「命令窗口显示问题」不是显示问题，是**根本没被消费**

**发现路径**：用户报告「命令窗口显示问题」⇒ 读 `dsh-anic` 的实现时发现
`ToolViewIntegration.ts:4-11` 记录了官方契约核验结论：**内置 Web Client 不消费
`presentCall` / `presentResult`**。

**核验**：`grep -rn "tool.call" src/` ⇒ **零命中**（本插件从未注册过 toolview 席位）；
`grep -c "tool.call.toolview" dist/client.js` ⇒ 修复前 0。

**为什么此前没被发现**：宿主侧把 `presentCall` / `presentResult` /
`presentationMeta` 构造得很完整（`tool-presentation.ts` 722 + 280 + 417 行），
且 `tests/contract/capability.test.ts` 有「注册处必须接线」的源码门
（`presentCall:` / `presentResult:` / `presentationMeta:` 三条都在）——
**接线是接上了，只是接到了没人消费的那一头**。

> **教训**：契约测试能证明「我调了这个钩子」，但证明不了「宿主会消费它」。
> 凡是「宿主侧投影」类能力，验收必须有一条**消费侧**的断言 ——
> 本轮落成 `tests/contract/toolview-contract.test.ts`（client 半部必须注册
> keyed slot）+ 真机判据 `__RECENCY_GUARD_TOOLVIEW__.count === 1`。

### 1.2 逐码点剥 ANSI 会把**可见字面量**留下

实测：`sanitizeText('safe\u001b[31mRED\u001b[0m')` ⇒ `'safe\\[31mRED\\[0m'`
（ESC 没了，负载 `[31m` 还在）。

**为什么以前没人发现**：终端里 `[31m` 不起眼（多数终端把它显示成普通文本），
但**在命令窗口的纯文本渲染里它是一串噪声**，而且语义丢失（本来是红色）。

**修法**：序列级剥除（CSI / OSC / DCS / 两字符转义 / 孤立 ESC / 裸 CR），
且必须是 `sanitizeText` 的**第一步**（序列被逐码点拆开后负载已无法识别为序列）。

> **教训**：剥除要**按层**剥，不是按字符剥。控制字符是「一层」，转义序列是
> 「另一层」；先拆序列再剥字符的顺序颠倒，会留下不可逆的残留。

### 1.3 「改了没生效」的真因可能是**产物是旧的**

`link:` / `file:` 安装下改了 `src/**` 但忘了重建 ⇒ 宿主跑的是上一版产物，
而插件照常加载、工具照常注册、面板照常出数 —— **只有行为是旧的，且不报错**。

用户会以为「改了没生效」，开发者会以为「代码有问题」。

**修法**：`build-freshness.ts`，三态上屏。两条自律：

- **版本取自 `package.json`**，不从产物正则捞 —— 实测从 `dist/index.js` 捞到
  `0.9.0`（产物里到处是形如 `0.9.0` 的字符串，正则捞到**第一个**匹配的）。
  那是**假事实**，比没有事实更坏（用户会以为装了旧版）。
- **缺产物 ⇒ 指纹 `null`**，不伪造。

**首版还有两个自己造的 bug，都是被探针抓出来的**：

1. 「无源码」分支返回 `stale: false` + reason 说「无法判定」—— **自相矛盾**：
   把「无法判定」显示成「正常」是假绿。已改为 `stale: null`。
2. 根定位用 `process.cwd()` ⇒ 桌面 profile 报「未找到插件根目录」
   （插件的 cwd 是**用户工作区**，不是安装目录）。已改为**模块自身位置**。

> **教训**：探针（先写一个跑真数据的小脚本，再写正式代码）比测试更早暴露问题。
> 本轮两次都是「先跑探针 → 看到不对 → 再写测试钉住」。

### 1.4 失败退避的 `Infinity` 分支**方向反了**

`nextFailureDelay` 初版用 `!Number.isFinite(n) ⇒ 首档`。而 `Infinity` 表示
「失败次数无穷」—— 恰恰是最该退避到底的情形，让它**最快重试**是反的。
探针抓到后已改为：NaN ⇒ 首档（不可知 ≠ 很糟）、`+Infinity` ⇒ 封顶档。

> **教训**：`Infinity` 在很多「防御性兜底」里被当垃圾值处理，但它在**语义上**
> 常常是极端值。区分 `NaN`（不可知）与 `Infinity`（极值）。

### 1.5 契约测试真的拦住了错误（不是走过场）

第一次提交能力清单时，我给 `guard.present.toolview` 声明了 `consumes:
['guard.tool.status']`，但**忘了在 `guard.tool.status` 的 `consumedBy` 里反向登记**
（以及 `guard.present.panel` 漏了 `guard.observe.freshness`）。

契约测试当场报出两条断链：

```
FAIL guard.present.panel literally records guard.observe.freshness as an upstream [...]
FAIL guard.tool.status literally records guard.present.toolview as a consumer []
```

> **教训**：「清单是投影、注册是真相」这条纪律的价值，恰恰体现在**双向**上。
> 单向登记（只写 consumes 不写 consumedBy）会让索引的可达性分析失真。

### 1.6 市场 PR 混进了**别人的条目**

第一次建市场 PR 时，分支是从上一轮的功能分支拉出来的 ⇒ PR 里多了一个
`data/plugins/xuanyuanchumo__dsh-codegraph-visualizer.yml`（另一个插件的条目）。
contributing.md 明写：「PR 动了别人的条目会被 gate 列出来追问」。

已从**上游 main 重新拉分支**，只应用自己那一条的改动（PR 文件数 4 → 3）。

> **教训**：市场投稿的分支必须**从上游 main 起**，不能从自己的工作分支起 ——
> 累积的提交会被一并带进 PR。

## 2. 关键决策记录

| 决策 | 选择 | 理由 | 被否决的替代方案 |
|---|---|---|---|
| 命令窗口卡片的注册形态 | `ctx.slots.inject('tool.call.toolview', …)` + keyed `key = 'recency_guard'` | 席位由宿主 ToolCallTree 声明，只在会话面板挂载时存在；提前 `register` 会撞「向未声明 slot 注册」⇒ 整个 entry 失败（面板全灭） | 直接 `register`（撞未声明 slot）；host 侧加投影钩子（内置 Client 不消费） |
| 卡片数据来源 | host 侧 `presentationMeta`（facts/sections/omitted） | 卡片**转述** host 的事实，不从正文猜结构；折叠态也不重新决定（否则形成第二真相源） | 卡片自己解析正文（结构会漂移） |
| 卡片组件位置 | `src/client/toolview/`（client 半部） | 内置 Client 在**浏览器侧**查表；放 host 半部则永远不会被渲染 | 放 host 半部（无法被 Client 消费） |
| 注册计数 | getter（`get count()`） | `inject` 回调是宿主**延迟**调用的（ToolCallTree 挂载时），静态快照会永远停在 0（anic 实测：5 卡片 vs count=0） | 静态对象（`{count: 0}` 永不更新） |
| ANSI 剥离层级 | 序列级，作为 `sanitizeText` 第一步 | 序列被逐码点拆开后负载已无法识别为序列 | 只剥 ESC（留可见负载）；只剥载荷（留 ESC） |
| 新鲜度三态 | `true` / `false` / **`null`** | 「无法判定」（发布态无 `src/`）必须与「判定为不旧」区分 —— 否则面板显示「产物与源码一致」是**假绿** | 二态（无法判定归入「不旧」） |
| 新鲜度版本来源 | `package.json` | 产物里到处是 `0.9.0` 这类字符串，正则捞第一个匹配 = **假事实** | 从产物正则捞 |
| 新鲜度扫描频率 | 宿主侧 60s TTL 缓存 | 递归扫 `src/` 是启动路径最贵的动作；面板 5~15s 轮询一次 ⇒ 不缓存就是每轮一次全树扫描 | 无缓存（每轮全扫） |
| 跨分区串扰防线 | 世代守卫（纯函数） | 「取消传输」（AbortController）≠「不落地」；守卫对不可取消的注入实现同样有效，且可测 | AbortController（管不到已 resolve 的 then） |
| 失败退避阶梯 | 5/10/20/40/60s | 前两次快速重试（多数是瞬时抖动）；之后宿主真挂的概率显著上升；封顶 60s 免得用户以为面板坏了 | 固定 5s（每 5s 打一次死掉的宿主）；内容退避兼用（失败时「内容变没变」无意义） |
| 隐藏页策略 | 推迟拉取 + 恢复即补拉 | 用户切回标签页的那一刻最想看新数据；停掉意味着最坏等 15s | 彻底停轮询（切回要等一个周期）；继续照常轮（白烧宿主资源） |
| npm 发布方式 | registry API 直连（一次 PUT + CouchDB 附件） | `vault_run` 的 cwd 固定在桌面 profile ⇒ 读不到本仓 `.npmrc` ⇒ ENEEDAUTH | `npm publish`（cwd 不可信）；先文档后附件（400 Must include a tarball） |
| 市场 PR 分支 | 从上游 main 新起 | 从自己的工作分支起会带上累积提交（PR 混进别人的条目） | 从功能分支起（已犯过一次） |
