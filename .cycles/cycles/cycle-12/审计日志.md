## 决策记录（为什么这样做）

| 决策 | 理由 |
|---|---|
| 本轮只做 07 的 M1–M4，不新增无关特性 | 上一轮跑道了四方向但漏了里程碑。先补缺口，不叠新功能（R09 计划模式优先） |
| M2 贝叶斯**并行读数**，不替换默认 | 07 §2.3 明文要求；且新模型未经真机验证，替换默认值等于用未验证的东西下决策 |
| 误伤来源靠「enable 段是否被 restore 收尾」判定 | `enable` 无 actor 字段，且不能改 `recovery-actions.ts`（超范围）。接受为启发式并登记 TD-1 |
| M4 由 Lead 接手（原 teammate 上下文耗尽） | 子代理失败后交付为零，与其重派不如自己写（已掌握测试运行器接口） |
| 变异工具用内存保存原文而非 `.bak` | `.bak` 本身成为仓库噪音且中断会残留；内存方案天然无残留 |
| 杀灭率不达标**不改阈值也不改断言含量** | 47.5% 是真实数字。把等价变异体算进去才是造假；正确做法是修工具 + 归因 |
| G1 首轮 FAIL 时不改任务清单状态 | R07「不条件通过」。真实做完了才标完成 |
| 07 的两条判据（命中率/预警提前量）明确「未声称」 | 没有真机样本。研究文档 05 §4 批评的正是「看起来绿」 |
| `index.ts` 拆 `status-projections.ts` | 复杂度预算按文件计分；旁路投影不该挤占崩溃恢复主线（cycle-5 既有惯例） |
