## 5. E4.2 故障注入（07 §5.2 判据：检出率 100%）

### 5.1 用例矩阵（8 个：5 正 3 反）

| 坏插件形态 | 通道 | 结果 |
|---|---|---|
| `apply-throw-required`（核心 entry apply 抛错） | 哨兵 | 检出 |
| `missing-dep-required`（import 期 ERR_MODULE_NOT_FOUND + 核心 entry） | 哨兵 | 检出 |
| `exit-now`（apply 里 `process.exit(1)`，进程级错误） | 哨兵 | 检出 |
| `async-throw-after-apply`（apply 成功后异步抛，时序缺陷） | 哨兵 | 检出 |
| `hard-kill`（挂载后父进程 SIGKILL，**不跑 exit 处理器**） | 异常终止 | 检出 |
| `apply-throw-optional`（非核心 entry，宿主自隔离） | — | 不误判 |
| `missing-dep-optional` | — | 不误判 |
| `good-plugin` | — | 不误判 |

**检出率 5/5 = 100%**；反向 3/3 无误判。

### 5.2 三个真实陷阱（都写进了夹具注释）

1. **entry 级失败不是崩溃**：cordis 把 apply 异常吞成 entry state=3(FAILED)，只有
   `requiredStartupEntryIds`（如 `webserver`）失败才会让 `auditStartupEntries` 抛
   `StartupError` 变成真 fatal。同一个夹具因此同时当正反用例 —— 锚定的是威胁模型边界，
   不是测试自己定义的「崩溃」。
2. **ESM 链接期会让 beacon 永不执行**：用静态 `import` 引缺失依赖时，连先写的
   `import './beacon.mjs'` 都不会被求值（链接期先解析全部静态依赖）。这正是
   「夹具顶层代码根本没被 import」这类假阳性的来源。改用 top-level `await import()`。
3. **测试脚本自身非零退出会被守护记成崩溃**：守护装的是进程级 exit 哨兵，
   子进程 `process.exit(3)` 会写 sentinel + publish decision，把「反向用例」伪造成
   「注入成功」（实测出现过 `crashSeq=1, decision.disable=[fi-good]`）。修法：两个
   子进程一律 exit 0 + 写 report 相位，父进程按相位判 FAIL。

### 5.3 runtime 缺失时的降级（诚实边界）

`FI_SIMULATE_NO_RUNTIME=1` ⇒ 打印 `SKIP 本层未评估（不是 PASS）` 且 **exit=1**
（把「没验证」暴露给 CI）；`FI_ALLOW_SKIP=1` 才 exit 0。「无法评估」≠「通过」。

### 6.1 该测试抓到的两处**真实缺陷**（本循环已修）

| 缺陷 | 实测证据 | 修复 |
|---|---|---|
| 指针/决策 `writeFileSync` 先截断后写 | 跨进程并发读到 **0 字节指针**（507 次采样 4 次空）；守护行表达式读到空 ⇒ catch ⇒ 放行 ⇒ 该轮守护整体失效 | `core/atomic-sync.ts`（临时文件 + renameSync，**同步**以满足崩溃路径纪律）；`decision.writeSafe` 改用它 |
| `writePartitionIndex` 无锁 read-modify-write | 4 子进程并发登记后索引条目 4/4、3/4、**2/4** | 原子提交 + 与落盘索引按 key 合并；残留窗口如实登记 TD-4 |

### 6.2 指针桥的已知边界（量化，不伪装成 0）

数据面：每个分区直读决策文件 100% 只含自己（6/6 PASS）。
指针桥（守护行表达式真实路径：读指针 → 读它指向的决策）：稳态**自读 1 / 跨分区读 N−1**。
这是 `decision.ts` 头注登记的已知边界（指针是 profile 级共享），**不是本轮并发新引入**；
断言它恰为 N−1，若超出则有额外串扰。因此「指针不会让 A 读到 B 的决策」这句**不成立**，
已如实上报并作为 M5 设计变更候选（TD-4 同族）。

## 9. 架构边界（新增的契约门）

`tests/contract/client-host-boundary.test.ts`：
1. client 源码不得有 `node:*` 的**运行时** import（`import type` 豁免，编译期擦除）；
2. client 源码不得 import `src/host/**` 的**运行时**模块；
3. **反向自检**：用合成违规样例验证判据真的会响（防正则写错后的「永远 0 违例」假绿）。

该门抓到并促成修复 **11 处真实越界**：client 的 graph 层原本直接 import
`host/capability/graph-data.ts` 的 `LAYOUT` 与类型 —— 这在开发期不报错，
但 client bundle 一旦打包，宿主能力会进浏览器图，且**只有用户打开面板时才炸**。
修法是抽出 `src/shared/graph-contract.ts`（类型 + 纯常量），host 与 client 各自依赖它、
互不依赖 —— 对应 dsh 的 Definition 角色。
