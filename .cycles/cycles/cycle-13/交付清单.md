## 4. 架构重构（用户中途指令，本循环最大改动）

### 4.1 依据（dsh 插件开发知识库）

- `packages/<group>/<pkg>/`：**group 是纯容器**，词表含 `client` / `host` / `core`；
- 一个 package 只承担一个运行时角色；client 插件包声明 `dsh.client`、导出 `./client`；
- 能力 seam 三角色：**Definition / Provider / Consumer**，Provider 与 Consumer 互不依赖。

本包一个 `package.json` 装两个入口（`main` + `exports["./client"]`）⇒ 第一层必须按
**运行时**切分（`host/` / `client/`），功能域在该边界内部再分。

### 4.2 交付结构

```
src/index.ts                    host bundle 入口（Loader 四件套）
src/host/{core,data,guard,profile,observe,risk,capability,surface}/
src/client/{panel,graph,api,i18n}/
src/shared/graph-contract.ts    跨运行时契约层（类型 + 纯常量）
```

### 4.3 边界写成测试（不是注释）

`tests/contract/client-host-boundary.test.ts`：client 不得有 `node:*` 运行时 import、
不得 import `src/host/**` 运行时模块（`import type` 豁免），并带回**反向自检**。

**它抓到并促成修复 11 处真实越界**：client 的 graph 层原本直接 import
`host/capability/graph-data.ts` 的 `LAYOUT` 与类型 —— 开发期不报错，但 client bundle
打包后宿主能力会进浏览器图，且**只有用户打开面板时才炸**。修法：抽出
`src/shared/graph-contract.ts`（Definition 角色），host 与 client 各依赖它、互不依赖。

### 4.4 循环依赖已证明消除

`tests/contract/import-graph.test.ts` 解析全部相对 import，区分**值边/类型边**并 DFS 找环：

- **值依赖图无环**（架构违例判据）；
- 仅存 1 个**类型**环（`surface/tool-render ↔ tool-presentation` 互引类型），按判据合法，
  显式 INFO 记录。

修复的两个真实环：`observability ↔ survival`、`observability ↔ control-band`
（度量契约与统计原语下沉到 `core/metric.ts`，10 个符号的最小必要集）。
